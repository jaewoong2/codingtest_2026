# [이코테 / 프로그래머스] 타겟 넘버 풀이 첨삭

## 총평
- **판정**: **정답 (Correct)**
- **핵심 이유**: 
  1. `collections.deque`를 활용한 너비 우선 탐색(BFS) 방식으로 모든 경우의 수($2^N$)를 효율적으로 완전 탐색했습니다.
  2. `(인덱스, 누적합)`을 상태 튜플로 구성하여 깔끔하게 탐색 흐름을 제어했습니다.
  3. 첫 번째 원소의 `+` / `-` 처리 두 가지 경우로 초기 큐를 세팅한 아이디어가 직관적이고 정확합니다.

---

## 문제 핵심
- $N$개의 정수 배열 `numbers`의 원소 순서를 바꾸지 않고 각 원소에 `+` 또는 `-` 부호를 붙여 총합이 `target`이 되는 **방법의 수**를 구해야 합니다.
- **핵심 제약**:
  - $N$ (숫자의 개수): 2개 이상 20개 이하
  - 각 숫자에 대해 선택할 수 있는 경우의 수: 2가지 (`+` 또는 `-`)
  - 전체 경우의 수: $2^{20} = 1,048,576$ (약 100만 회 연산)
- $N$이 매우 작으므로 지수 시간 $O(2^N)$의 **완전 탐색(BFS / DFS)** 접근이 정답 알고리즘입니다.

---

## 현재 접근법 평가

사용자께서 작성하신 BFS 접근법은 매우 명확하며 모범적인 코드입니다.

1. **상태 정의**: `(index, value)` 튜플로 현재까지 선택한 숫자 위치와 누적 합을 관리.
2. **초기 세팅**: `(0, array[0])`과 `(0, -array[0])`을 큐에 미리 넣어 시작.
3. **종료 조건**: `index + 1 == len(array)`일 때 `value == target`이면 `answer += 1`.
4. **전이(Transition)**: 다음 원소 `array[index + 1]`에 대해 `+`와 `-` 두 방향으로 가지치기 진행.

---

## 복잡도 분석

- $N$: `numbers` 배열의 길이 (최대 20)
- **시간 복잡도**: $O(2^N)$
  - 각 단계마다 2가지 선택지가 생기며, 총 $N$단계 탐색합니다.
  - $2^{20} \approx 1,048,576$ 번 연산하므로 1초 제한 대비 매우 여유롭습니다 (약 0.05초 소요).
- **공간 복잡도**: $O(2^N)$
  - 레벨 단위 탐색(BFS) 특성상 마지막 깊이에서 큐에 최대 $2^{N-1}$ 개의 노드가 저장됩니다.
  - $N=20$일 때 큐의 최대 크기는 $2^{19} \approx 524,288$ 개로, 파이썬 메모리 제한 내에서 문제없이 동작합니다.

---

## 선택적 개선 제안 (DFS & 관용적 표현)

현재 정답 코드도 훌륭하지만, 이 문제의 특성상 **DFS(재귀) 방식**을 사용하면 메모리를 훨씬 적게 쓰고 코드를 더 짧게 작성할 수 있습니다.

### 1. DFS(재귀) 방식과의 비교
BFS는 큐에 최대 $O(2^N)$개의 상태를 저장을 해야 하지만, **DFS(재귀)**는 호출 스택 깊이가 최대 $O(N)$에 불과하므로 메모리를 훨씬 아낄 수 있습니다.

```python
# DFS (재귀) 풀이 - 메모리 공간 O(N)
def solution(numbers, target):
    def dfs(index, current_sum):
        # 모든 숫자를 다 사용했을 때
        if index == len(numbers):
            return 1 if current_sum == target else 0
        
        # 현재 숫자를 더하는 경우 + 뺄 때의 경우의 수 합
        return dfs(index + 1, current_sum + numbers[index]) + \
               dfs(index + 1, current_sum - numbers[index])

    return dfs(0, 0)
```

---

### 2. 파이썬 `itertools.product`를 활용한 한 줄 풀이
파이썬의 데카르트 곱(`product`) 라이브러리를 활용하면 모든 `+`, `-` 조합을 쉽게 만들 수도 있습니다.

```python
from itertools import product

def solution(numbers, target):
    # 각 숫자에 대해 (x, -x) 튜플 생성
    l = [(x, -x) for x in numbers]
    # 모든 조합의 합이 target인 개수를 카운트
    return sum(1 for s in product(*l) if sum(s) == target)
```

---

## 이 문제에서 읽어야 할 신호 (알고리즘 선택 가이드)

1. **"N이 매우 작다 ($N \le 20$)" + "모든 경우를 확인해야 한다"**
   - ⭐ **신호**: $2^{20} \approx 100\text{만}$이므로 시간 초과 걱정 없이 **완전 탐색 (DFS / BFS)**을 바로 선택해야 합니다.

2. **"모든 숫자를 끝까지 사용해야 결과를 알 수 있다"**
   - ⭐ **신호**: 굳이 레벨 단위로 모든 노드를 큐에 담는 BFS보다는, 끝까지 들어갔다 나오는 **DFS (재귀)**가 메모리 공간 효율성($O(N)$ vs $O(2^N)$) 면에서 선호됩니다.
