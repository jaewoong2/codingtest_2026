# DP - 실전 5번 효율적인 화폐 구성 첨삭

## 총평

- 판정: **오답**
- 현재 입력에서는 5가 출력되어 맞습니다.
- 전체적인 접근은 이 문제의 정석인 1차원 DP입니다.
- 다만 목표 금액보다 큰 동전이 입력될 수 있으면 dp[coin]에서 인덱스 오류가 발생합니다.
- 초기 상태를 dp[0] = 0으로 두고 모든 금액을 같은 점화식으로 계산하면 더 안전하고 이해하기 쉽습니다.

---

## 1. 문제 핵심

N개의 화폐 종류가 주어지고, 각 화폐를 여러 번 사용할 수 있다고 하겠습니다.

목표는 화폐를 사용하여 금액 M을 만들 때 필요한 화폐 개수의 최솟값을 구하는 것입니다.

만들 수 없다면 -1을 출력합니다.

예를 들어 현재 입력:

~~~text
2 15
2
3
~~~

에서는:

~~~text
3 + 3 + 3 + 3 + 3 = 15
~~~

이므로 정답은 5입니다.

---

## 2. 현재 풀이의 접근법

현재 코드는 금액별 최소 화폐 개수를 저장하는 DP를 사용했습니다.

~~~python
dp = [float("INF") for _ in range(target + 1)]
~~~

그리고 동전 하나로 만들 수 있는 금액은 1개로 초기화합니다.

~~~python
for coin in coins:
    dp[coin] = 1
~~~

이후 금액을 작은 것부터 확인하면서, 현재 동전을 하나 추가하는 방법을 비교합니다.

~~~python
dp[value] = min(dp[value], dp[value - coin] + 1)
~~~

이 방식은 방향 자체는 정확합니다.

---

## 3. DP 상태 정의

이 문제에서 가장 중요한 상태는 다음입니다.

~~~text
dp[value] = value를 만들기 위해 필요한 최소 동전 개수
~~~

초기 상태는 다음과 같이 두는 것이 가장 자연스럽습니다.

~~~text
dp[0] = 0
~~~

금액 0은 동전을 하나도 사용하지 않으면 만들 수 있기 때문입니다.

그 후 금액 value를 만들 때 동전 coin을 마지막에 하나 사용한다고 생각합니다.

그러면 그 전에는 value - coin을 만들어야 합니다.

~~~text
value를 만드는 방법
= value - coin을 만드는 최소 방법 + coin 하나
~~~

따라서 점화식은:

~~~python
dp[value] = min(dp[value], dp[value - coin] + 1)
~~~

입니다.

---

## 4. 현재 코드의 필수 오류

현재 코드에는 다음 부분이 있습니다.

~~~python
for coin in coins:
    dp[coin] = 1
~~~

문제는 coin이 target보다 클 수 있다는 점입니다.

### 반례 입력

~~~text
2 3
5
10
~~~

목표 금액은 3인데, 동전은 5와 10입니다.

정답은 만들 수 없으므로:

~~~text
-1
~~~

이어야 합니다.

하지만 현재 코드는 다음과 같이 동작합니다.

~~~python
dp = [INF, INF, INF, INF]
dp[5] = 1
~~~

dp의 마지막 인덱스는 3인데 dp[5]에 접근하므로:

~~~text
IndexError: list assignment index out of range
~~~

가 발생합니다.

따라서 표준 문제처럼 동전의 가치가 목표 금액보다 클 수 있다면 반드시 수정해야 합니다.

---

## 5. 더 안전한 초기화 방법

동전의 값을 미리 dp[coin]에 넣지 말고, dp[0]만 초기화한 뒤 모든 금액을 같은 점화식으로 처리하는 것이 좋습니다.

~~~python
dp = [float("inf")] * (target + 1)
dp[0] = 0
~~~

그리고:

~~~python
for value in range(1, target + 1):
    for coin in coins:
        if value >= coin:
            dp[value] = min(dp[value], dp[value - coin] + 1)
~~~

이렇게 하면:

- coin이 target보다 커도 문제 없음
- value와 coin이 같은 경우도 자연스럽게 처리
- dp[coin]을 별도로 초기화할 필요 없음
- target이 0이어도 dp[0] = 0으로 처리 가능

---

## 6. 추천 구현

~~~python
def solution():
    n, target = map(int, input().split())
    coins = [int(input()) for _ in range(n)]

    INF = float("inf")
    dp = [INF] * (target + 1)
    dp[0] = 0

    for value in range(1, target + 1):
        for coin in coins:
            if value >= coin and dp[value - coin] != INF:
                dp[value] = min(dp[value], dp[value - coin] + 1)

    if dp[target] == INF:
        return -1

    return dp[target]
~~~

dp[value - coin]이 INF인지 확인하는 이유는, 이전 금액을 만들 수 없는 상태라면 거기에 1을 더해도 실제 해답이 아니기 때문입니다.

Python의 float inf에 1을 더해도 inf이므로 현재 코드에서도 계산은 가능하지만, 조건을 적어두면 의미가 더 분명합니다.

---

## 7. 현재 코드의 조건문 검토

현재 조건은 다음과 같습니다.

~~~python
if value > coin and value - coin > 0:
~~~

두 조건 중 두 번째는 필요하지 않습니다.

value > coin이면 항상 value - coin > 0이기 때문입니다.

추천 구현에서는 다음처럼 바꿉니다.

~~~python
if value >= coin:
~~~

value와 coin이 같은 경우도 허용해야 합니다.

예를 들어 동전 5 하나로 금액 5를 만드는 경우:

~~~text
dp[5] = dp[0] + 1 = 1
~~~

이 계산이 가능해야 합니다.

현재 코드는 이 경우를 dp[coin] = 1로 미리 넣었기 때문에 동작하지만, dp[0] 기반 방식에서는 value >= coin이 필요합니다.

---

## 8. 왜 금액을 작은 순서로 계산하는가?

dp[value]를 계산하려면 dp[value - coin]이 필요합니다.

모든 동전의 가치는 양수이므로:

~~~text
value - coin < value
~~~

입니다.

따라서 금액을 1부터 target까지 순서대로 계산하면 필요한 이전 상태가 항상 먼저 계산되어 있습니다.

예를 들어 coin이 3이고 value가 8이라면:

~~~text
dp[8]을 계산하기 위해 dp[5]가 필요
dp[5]는 이미 계산 완료
~~~

이것이 바텀업 DP가 가능한 이유입니다.

---

## 9. 이 문제는 어떤 DP 유형인가?

이 문제는 **동전 개수의 최솟값을 구하는 완전 배낭 문제**로 볼 수 있습니다.

완전 배낭이라는 뜻은:

> 같은 동전을 여러 번 사용할 수 있다.

예를 들어 동전 2가 있다면:

~~~text
2, 2 + 2, 2 + 2 + 2, ...
~~~

처럼 계속 사용할 수 있습니다.

현재 코드는 금액을 작은 순서로 계산하므로 동전을 여러 번 사용하는 것이 자연스럽게 허용됩니다.

---

## 10. 다른 풀이가 있는가?

현재의 1차원 DP가 가장 적합한 정석 풀이입니다.

### 방법 1: 바텀업 1차원 DP

현재 사용한 방식입니다.

~~~text
시간 복잡도: O(N x M)
공간 복잡도: O(M)
~~~

- N: 동전 종류 수
- M: 목표 금액

각 금액마다 모든 동전을 확인합니다.

이 문제에서는 가장 이해하기 쉽고 안정적인 방법입니다.

### 방법 2: 탑다운 DP와 메모이제이션

재귀적으로 필요한 금액만 계산할 수도 있습니다.

~~~python
def solve(value):
    if value == 0:
        return 0

    if value < 0:
        return INF

    if memo[value] != -1:
        return memo[value]

    memo[value] = min(
        solve(value - coin) + 1
        for coin in coins
    )

    return memo[value]
~~~

하지만 음수 상태를 처리해야 하고 재귀 깊이 문제도 생길 수 있습니다.

시간 복잡도는 메모이제이션이 제대로 되면 바텀업과 비슷한 O(N x M)입니다.

이 문제에서는 현재처럼 반복문으로 푸는 방식이 더 안전합니다.

### 방법 3: BFS

금액을 정점으로 생각할 수도 있습니다.

~~~text
현재 금액 value에서
value + coin으로 이동
~~~

각 동전 사용이 비용 1인 간선이므로, target에 처음 도달하는 깊이가 최소 동전 개수가 됩니다.

하지만 금액이 0부터 target까지이고 모든 간선 비용이 같기 때문에, 이 문제에서는 DP가 더 직접적입니다.

BFS를 사용하면 방문 배열과 큐가 추가로 필요합니다.

### 방법 4: 그리디

가장 큰 동전부터 사용하는 방법은 일반적으로 사용할 수 없습니다.

반례:

~~~text
동전: 1, 3, 4
목표: 6
~~~

그리디:

~~~text
4 + 1 + 1 = 6
동전 3개
~~~

최적해:

~~~text
3 + 3 = 6
동전 2개
~~~

따라서 동전 종류가 특별히 정렬된 규칙을 가지지 않는 이상 그리디는 정답을 보장하지 않습니다.

## 11. 작은 예시로 DP 확인하기

동전이 2와 3이고 목표가 15인 경우:

~~~text
dp[0] = 0

dp[1] = INF
dp[2] = dp[0] + 1 = 1
dp[3] = dp[0] + 1 = 1
dp[4] = dp[2] + 1 = 2
dp[5] = dp[2] + 1 = 2
dp[6] = min(dp[4] + 1, dp[3] + 1) = 2
...
dp[15] = 5
~~~

실제 조합은:

~~~text
3 + 3 + 3 + 3 + 3
~~~

입니다.

## 13. 현재 코드의 선택적 개선

### 리스트 생성

현재 코드:

~~~python
dp = [float("INF") for _ in range(target + 1)]
~~~

다음처럼 줄일 수 있습니다.

~~~python
dp = [float("inf")] * (target + 1)
~~~

### 결과 반환

현재 코드:

~~~python
return dp[target] == float("INF") and -1 or dp[target]
~~~

조건부 표현식처럼 보이지만, 읽기 어렵고 값이 0인 경우 오해를 만들 수 있습니다.

다음처럼 명시적으로 작성하는 편이 좋습니다.

~~~python
if dp[target] == INF:
    return -1

return dp[target]
~~~

### 변수명

target도 괜찮지만, 문제의 M을 그대로 사용하기보다 다음처럼 의미를 드러내는 이름도 좋습니다.

~~~python
amount
~~~

다만 현재 변수명이 정답 여부에 영향을 주는 문제는 아닙니다.

## 14. 복잡도

N을 동전 종류 수, M을 목표 금액이라고 하겠습니다.

금액 1부터 M까지 각각 확인하고, 각 금액마다 N개의 동전을 확인합니다.

~~~text
총 반복 횟수 = M x N
시간 복잡도: O(NM)
~~~

dp 배열에는 0부터 M까지 저장하므로:

~~~text
공간 복잡도: O(M)
~~~

동전 사용 횟수의 최소값만 필요하므로 2차원 배열은 필요하지 않습니다.

## 15. 문제에서 읽어야 할 신호

다음 표현은 DP를 떠올리게 합니다.

- 동전을 여러 번 사용할 수 있다.
- 목표 금액을 만든다.
- 필요한 동전 개수의 최솟값을 구한다.
- 동전 종류가 일반적이어서 그리디가 항상 보장되지 않는다.
- 이전 금액의 결과를 이용해 현재 금액을 만들 수 있다.

특히 다음 질문을 해보면 됩니다.

> 마지막에 어떤 동전 하나를 사용했다고 생각하면, 그 전에 필요한 금액은 얼마인가?

마지막 동전이 coin이라면:

~~~text
현재 금액 value
→ 이전 금액 value - coin
→ 동전 coin 하나 추가
~~~

따라서:

~~~text
dp[value] = dp[value - coin] + 1
~~~

이 구조가 보이면 1차원 DP를 먼저 검토하면 됩니다.

## 16. 다음 문제에서 점화식을 떠올리는 순서

1. dp[value]의 의미를 한 문장으로 정의합니다.
2. 가장 작은 상태인 dp[0]을 정합니다.
3. 마지막에 선택되는 동전 하나를 생각합니다.
4. 그 동전을 사용하기 전의 금액을 찾습니다.
5. 이전 상태의 답에 현재 동전 하나를 더합니다.
6. 가능한 동전 중 최솟값을 선택합니다.
7. 만들 수 없는 상태는 INF로 남깁니다.
8. 마지막 dp[target]이 INF인지 확인합니다.

이 문제의 점화식은 다음 한 줄로 정리할 수 있습니다.

~~~text
현재 금액의 최소 동전 수
= 마지막 동전을 빼고 남은 금액의 최소 동전 수 + 1
~~~

1. 동전을 한 번만 사용할 수 있는가, 여러 번 사용할 수 있는가?
2. 목표 금액보다 큰 동전이 입력될 수 있는가?
3. dp[0]의 의미는 무엇인가?
4. 동전 하나로 바로 만들 수 있는 금액은 어떻게 처리되는가?
5. 만들 수 없는 금액은 어떤 값으로 저장할 것인가?
6. 가장 큰 동전부터 선택하는 그리디가 항상 최적인가?
7. 동전의 사용 순서가 달라도 같은 조합으로 처리해도 되는가?
8. 목표 금액이 0이거나 동전보다 작은 경우를 확인했는가?
9. 마지막 동전 하나를 기준으로 점화식을 설명할 수 있는가?
10. 결과에 나머지 연산이나 출력 형식 조건이 있는가?

이번 문제에서 가장 중요한 교훈은 다음입니다.

> 동전 문제에서 금액을 상태로 두고, 마지막에 사용한 동전 하나를 제거했을 때의 최소값을 재사용하면 된다. 현재 풀이의 방향은 맞지만, dp[0] = 0에서 시작하면 초기화와 예외 처리가 훨씬 안전해진다.
