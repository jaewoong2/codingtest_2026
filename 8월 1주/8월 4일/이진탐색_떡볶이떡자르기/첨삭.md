# 이진탐색 - 떡볶이 떡 자르기 첨삭

## 총평

- 판정: **정답**
- 기준: 절단기 높이는 정수이고, 목표로 하는 떡의 길이는 양수이며, 목표량을 만들 수 있다는 일반적인 문제 조건
- 핵심 이유: 절단기의 높이가 높아질수록 얻는 떡의 양이 줄어드는 단조성을 이용해, 조건을 만족하는 높이 중 최댓값을 이진 탐색하고 있습니다.

현재 입력을 실행하면 다음 결과가 나옵니다.

```text
15
```

예제에서 절단기 높이를 15로 설정하면:

```text
(19 - 15) + (15 - 15) + (10 - 15) + (17 - 15)
= 4 + 0 + 0 + 2
= 6
```

목표량 6을 정확히 만들 수 있습니다.

---

## 1. 문제 핵심

입력은 다음과 같습니다.

- `N`: 떡의 개수
- `M`: 가져가야 하는 떡의 최소 길이
- `array`: 각 떡의 높이

절단기 높이를 `H`라고 하면, 각 떡에서 얻는 길이는 다음과 같습니다.

```python
max(떡의 높이 - H, 0)
```

따라서 전체 떡의 양은 다음과 같습니다.

```python
sum(max(x - H, 0) for x in array)
```

구해야 하는 값은 다음입니다.

> 떡을 최소 `M`만큼 얻을 수 있는 절단기 높이 중 최댓값

---

## 2. 현재 풀이의 접근법

현재 코드는 절단기 높이 `mid`를 이진 탐색하고 있습니다.

```python
value = sum([max(x - mid, 0) for x in array])
```

이후 얻은 떡의 양이 목표량 이상인지 확인합니다.

```python
if value >= target:
    result = max(result, mid)
    minium = mid + 1
else:
    maximum = mid
```

이 판단은 올바릅니다.

- `value >= target`: 떡이 충분함 → 절단기를 더 높여도 되는지 확인
- `value < target`: 떡이 부족함 → 절단기를 낮춰야 함

---

## 3. 왜 이진 탐색이 가능한가?

절단기 높이와 얻는 떡의 양을 생각해 보면 다음과 같습니다.

```text
절단기 높이 H가 낮음  → 얻는 떡이 많음
절단기 높이 H가 높음  → 얻는 떡이 적음
```

예를 들어 어떤 입력에서 조건을 확인하면 다음처럼 됩니다.

```text
높이 H:       0   1   2   3   4   5   6
떡 충분 여부:  T   T   T   T   T   F   F
```

`T`는 목표량 이상을 얻을 수 있다는 뜻입니다.

이 문제는 `T` 중에서 가장 오른쪽에 있는 값, 즉 **마지막으로 조건을 만족하는 높이**를 찾는 문제입니다.

이처럼 어떤 조건이 한쪽에서는 계속 참이고, 다른 쪽에서는 계속 거짓인 구조를 단조성이라고 합니다.

---

## 4. `minimum < maximum`과 `<=`의 차이

`<`와 `<=` 중 무엇이 항상 정답인 것은 아닙니다.

먼저 탐색 구간을 어떻게 정의했는지가 중요합니다.

### 방식 A: 양 끝을 포함하는 구간

```text
[low, high]
```

`low`와 `high` 모두 탐색 대상입니다.

이 경우에는 다음과 같이 작성합니다.

```python
while low <= high:
```

`mid`가 실패했다면 `mid`는 다시 볼 필요가 없으므로:

```python
high = mid - 1
```

를 사용합니다.

### 방식 B: 오른쪽 끝을 제외하는 구간

```text
[low, high)
```

`low`는 포함하지만 `high`는 포함하지 않는 구간입니다.

이 경우에는 다음과 같이 작성합니다.

```python
while low < high:
```

`mid`가 실패했다면 `mid`를 새 구간에 포함하지 않도록:

```python
high = mid
```

를 사용합니다.

현재 코드는 사실상 이 방식에 가깝습니다.

```python
while minium < maximum:
    ...
    else:
        maximum = mid
```

따라서 현재 코드에서 `maximum = mid`는 잘못된 코드가 아닙니다. 다만 `maximum`을 포함 범위의 끝으로 생각하면 헷갈리기 때문에, 초보 단계에서는 방식 A를 권장합니다.

---

## 5. `mid + 1`, `mid`, `mid - 1`을 결정하는 방법

외우기보다 다음 질문을 하면 됩니다.

> 지금 `mid`는 다음 탐색에서 다시 확인할 필요가 있는가?

### 조건을 만족하는 경우

```python
value >= target
```

현재 높이 `mid`는 정답 후보입니다.

하지만 이 문제는 **가장 높은 가능한 높이**를 찾아야 하므로, 더 높은 높이를 확인해야 합니다.

```python
answer = mid
low = mid + 1
```

`mid` 자체는 이미 `answer`에 저장했으므로 다음 탐색에서는 제외합니다.

### 조건을 만족하지 못하는 경우

```python
value < target
```

현재 높이 `mid`에서는 떡이 부족합니다.

따라서 `mid`보다 높은 높이는 모두 실패합니다. 포함 구간 방식을 사용한다면:

```python
high = mid - 1
```

을 사용합니다.

정리하면:

```text
조건 만족 + 최댓값 찾기 → 더 큰 쪽 탐색 → low = mid + 1
조건 실패              → 더 작은 쪽 탐색 → high = mid - 1
```

---

## 6. 현재 코드의 정확성 검토

현재 코드의 핵심 부분입니다.

```python
while minium < maximum:
    mid = (minium + maximum) // 2
    value = sum([max(x - mid, 0) for x in array])

    if value >= target:
        result = max(result, mid)
        minium = mid + 1
    else:
        maximum = mid
```

표준 문제 조건에서 다음 불변식이 유지됩니다.

1. `result`에는 지금까지 확인한 높이 중 조건을 만족한 가장 큰 값이 저장됩니다.
2. `minium`보다 작은 높이는 이미 확인했거나 더 좋은 답이 될 수 없습니다.
3. `maximum` 이상인 높이는 조건을 만족할 수 없습니다.

조건을 만족하면 `minium = mid + 1`로 더 높은 높이를 탐색하고, 조건을 만족하지 못하면 `maximum = mid`로 더 낮은 범위만 남깁니다.

따라서 탐색이 끝났을 때 `result`가 조건을 만족하는 최대 높이가 됩니다.

## 7. 경계 조건과 반례 확인

### 예제 입력

```text
4 6
19 15 10 17
```

기대 출력:

```text
15
```

현재 코드 출력도 `15`입니다.

### 목표량이 전체 떡의 합과 같은 경우

```text
3 6
1 2 3
```

절단기 높이를 0으로 해야 전체 합 6을 얻을 수 있습니다.

기대 답:

```text
0
```

현재 코드도 0을 반환합니다.

### 모든 떡의 높이가 같은 경우

```text
3 6
5 5 5
```

절단기 높이가 3이면 각 떡에서 2씩 얻어 총 6이 됩니다.

기대 답:

```text
3
```

### 목표량이 0인 경우

```text
2 0
5 5
```

문제 조건에서 `target >= 1`이라면 고려하지 않아도 됩니다. 하지만 목표량 0도 허용된다면, 최대 높이 5에서도 얻는 떡의 양이 0이므로 정답은 5입니다.

현재 코드는 `maximum = max(array)`를 제외 경계처럼 사용하기 때문에 4를 반환할 수 있습니다.

목표량 0까지 처리해야 한다면 양 끝 포함 방식으로 바꾸는 것이 안전합니다.

## 8. 추천하는 구현

현재 코드의 아이디어를 양 끝 포함 방식으로 정리하면 다음과 같습니다.

```python
def solution():
    n, target = map(int, input().split())
    array = list(map(int, input().split()))

    answer = 0
    low = 0
    high = max(array)

    while low <= high:
        mid = (low + high) // 2

        # 리스트를 따로 만들지 않고 바로 합산
        value = sum(max(x - mid, 0) for x in array)

        if value >= target:
            # mid는 가능한 높이
            answer = mid

            # 더 높은 높이도 가능한지 확인
            low = mid + 1
        else:
            # mid는 불가능하므로 제외
            high = mid - 1

    return answer
```

현재 코드와 알고리즘은 같지만, 다음 점이 더 명확합니다.

- `low`, `high`가 모두 탐색 대상이라는 점
- 실패한 `mid`를 `high = mid - 1`로 제거한다는 점
- `answer`를 조건을 만족할 때 바로 갱신한다는 점
- `sum([...])` 대신 generator를 사용해 임시 리스트를 만들지 않는 점

## 9. 복잡도

`N`을 떡의 개수, `H`를 가장 큰 떡의 높이라고 하겠습니다.

절단기 높이 하나를 검사할 때 모든 떡을 확인하므로:

```text
검사 1회: O(N)
```

높이 범위를 절반씩 줄이므로 검사 횟수는:

```text
O(log H)
```

전체 시간 복잡도는:

```text
O(N log H)
```

현재 코드의 리스트 컴프리헨션은 매번 최대 `N`개의 임시 리스트를 만들기 때문에 추가 공간을 사용합니다.

```python
sum([max(x - mid, 0) for x in array])
```

다음처럼 generator를 사용하면 추가 리스트 공간을 줄일 수 있습니다.

```python
sum(max(x - mid, 0) for x in array)
```

## 10. 선택적 개선

### 변수명 수정

현재 변수명은 `minium`으로 오타가 있습니다.

```python
minimum
```

보다 짧고 일반적으로는 다음 이름을 많이 사용합니다.

```python
low, high
```

### `n` 사용 여부

현재 `n`은 입력만 받고 이후에는 사용하지 않습니다.

입력 조건상 배열의 길이가 항상 `n`이라고 보장된다면 문제는 없지만, 다음처럼 작성하면 더 자연스럽습니다.

```python
array = list(map(int, input().split()))
```

### 정렬하지 않아도 됨

이 문제는 떡의 높이 순서와 상관없이 전체 합만 계산하므로 배열을 정렬할 필요가 없습니다.

## 11. 이 문제에서 읽어야 할 신호

문제에서 다음 표현을 발견하면 파라메트릭 서치를 떠올릴 수 있습니다.

- 절단기의 높이를 정해야 한다.
- 높이에 따라 얻는 양이 달라진다.
- 목표량 이상을 얻어야 한다.
- 가능한 높이 중 최댓값을 구한다.

특히 다음 질문을 해보면 됩니다.

> 높이 `H`가 가능하다고 할 때, 더 낮은 높이도 항상 가능한가?

이 문제에서는 그렇습니다.

- 높이 `H`가 가능하면 더 낮은 높이도 가능
- 높이 `H`가 불가능하면 더 높은 높이도 불가능

이런 단조성이 있기 때문에 이진 탐색을 적용할 수 있습니다.

## 다음 문제를 위한 체크포인트

1. 무엇을 이진 탐색할 것인지 먼저 정한다. 이 문제에서는 배열 값이 아니라 절단기 높이이다.
2. `가능하다 / 불가능하다`를 판단하는 함수를 만든다.
3. 조건을 만족하면 답을 저장하고 더 좋은 방향을 탐색한다.
4. `low`, `high`가 포함 범위인지 제외 범위인지 먼저 결정한다.
5. 현재 `mid`를 다음 탐색에서 다시 볼 필요가 있는지 판단한다.
6. 최대값을 찾는지, 최소값을 찾는지에 따라 탐색 방향을 정한다.

이 문제의 핵심 한 줄은 다음입니다.

```text
떡이 충분하면 절단기를 높이고, 부족하면 절단기를 낮춘다.
```

`mid + 1`과 `mid - 1`은 별도로 외우는 값이 아니라, 이미 확인한 `mid`를 다음 범위에서 제외하기 위해 사용하는 값입니다.
