# DP - 실전 3번 개미 전사 첨삭

## 총평

- 판정: **오답**
- 현재 예제 입력에서는 8이 출력되어 맞습니다.
- 하지만 DP의 두 번째 초기 상태가 잘못되어 특정 입력에서 최댓값을 놓칩니다.
- 점화식의 핵심 방향은 올바르게 잡았고, 초기값과 상태 정의를 일관되게 수정하면 해결할 수 있습니다.

---

## 1. 문제 핵심

식량 창고가 일렬로 놓여 있고, 인접한 창고를 동시에 털 수 없다고 하겠습니다.

각 창고에 들어 있는 식량의 양이 다음과 같을 때:

~~~text
1 3 1 5
~~~

인접하지 않은 창고를 선택하여 얻을 수 있는 식량의 최댓값을 구해야 합니다.

예를 들어:

- 0번과 2번 선택: 1 + 1 = 2
- 0번과 3번 선택: 1 + 5 = 6
- 1번과 3번 선택: 3 + 5 = 8

따라서 정답은 8입니다.

---

## 2. 현재 풀이의 접근법

현재 코드는 DP 배열에 각 위치까지의 최댓값을 저장하려고 합니다.

~~~python
dp = [arr[0], arr[1]]
~~~

그리고 2번 창고부터 다음 점화식을 사용합니다.

~~~python
dp.append(max(dp[i - 1], dp[i - 2] + arr[i]))
~~~

이 점화식의 방향은 정확합니다.

- 현재 창고를 털지 않는다: dp[i - 1]
- 현재 창고를 턴다: dp[i - 2] + arr[i]

현재 창고를 털면 바로 앞 창고는 털 수 없기 때문에 i - 2번까지의 최댓값에 현재 식량을 더합니다.

---

## 3. DP 상태 정의

현재 문제에서 가장 자연스러운 상태 정의는 다음과 같습니다.

~~~text
dp[i] = 0번부터 i번 창고까지 고려했을 때 얻을 수 있는 식량의 최댓값
~~~

이 정의를 사용하면 초기값은 다음과 같아야 합니다.

~~~text
dp[0] = arr[0]
dp[1] = max(arr[0], arr[1])
~~~

1번 창고까지 고려할 때는 다음 두 가지 중 하나를 선택할 수 있습니다.

- 0번 창고 선택
- 1번 창고 선택

두 창고를 모두 선택할 수는 없으므로 둘 중 큰 값을 가져야 합니다.

하지만 현재 코드는:

~~~python
dp = [arr[0], arr[1]]
~~~

로 작성되어 있어 0번 창고를 선택하는 경우를 dp[1]에서 잃어버릴 수 있습니다.

---

## 4. 반례 찾기

반례는 무작정 큰 입력을 만드는 것이 아니라, 코드가 결정하는 지점을 작게 쪼개서 만들면 쉽게 찾을 수 있습니다.

현재 코드에서 가장 의심스러운 부분은 다음입니다.

~~~python
dp = [arr[0], arr[1]]
~~~

여기서 질문을 해봅니다.

> 1번 창고까지 고려할 때 arr[0]이 arr[1]보다 큰 경우를 제대로 처리하고 있는가?

그렇지 않습니다.

따라서 다음처럼 0번 창고가 매우 크고 1번 창고가 작은 입력을 만들어볼 수 있습니다.

~~~text
100 0
~~~

하지만 창고가 2개인 경우에는 문제의 뒤쪽 계산에서 오류가 잘 드러나지 않을 수 있습니다. 그러므로 0번 창고의 큰 값을 나중에 다시 선택해야 하는 구조를 추가합니다.

~~~text
100 0 0 200
~~~

---

## 5. 구체적인 반례

### 반례 입력

~~~text
4
100 0 0 200
~~~

### 기대 결과

0번 창고와 3번 창고를 선택할 수 있습니다.

두 창고는 인접하지 않았으므로:

~~~text
100 + 200 = 300
~~~

기대 출력:

~~~text
300
~~~

### 현재 코드의 계산

현재 초기화:

~~~text
dp[0] = 100
dp[1] = 0
~~~

이후 계산:

~~~text
dp[2] = max(dp[1], dp[0] + arr[2])
      = max(0, 100 + 0)
      = 100

dp[3] = max(dp[2], dp[1] + arr[3])
      = max(100, 0 + 200)
      = 200
~~~

현재 코드의 결과:

~~~text
200
~~~

0번 창고의 100을 3번 창고와 함께 선택할 수 있었지만, dp[1]에 0번 창고의 값이 저장되어 있지 않아 그 가능성을 잃어버렸습니다.

---

## 6. 수정해야 하는 초기값

다음처럼 수정해야 합니다.

~~~python
dp = [0] * n
dp[0] = arr[0]
dp[1] = max(arr[0], arr[1])
~~~

이제 같은 반례를 계산하면:

~~~text
dp[0] = 100
dp[1] = max(100, 0) = 100
dp[2] = max(100, 100 + 0) = 100
dp[3] = max(100, 100 + 200) = 300
~~~

정답인 300을 얻을 수 있습니다.

---

## 7. 점화식이 성립하는 이유

i번 창고를 기준으로 두 가지 경우만 생각하면 됩니다.

### i번 창고를 털지 않는 경우

i번 창고를 털지 않으면 0번부터 i - 1번까지의 최적해를 그대로 사용하면 됩니다.

~~~python
dp[i - 1]
~~~

### i번 창고를 터는 경우

i번 창고를 털면 i - 1번 창고는 털 수 없습니다.

따라서 0번부터 i - 2번까지의 최적해에 i번 창고의 식량을 더합니다.

~~~python
dp[i - 2] + arr[i]
~~~

두 경우 중 더 큰 값을 선택합니다.

~~~python
dp[i] = max(dp[i - 1], dp[i - 2] + arr[i])
~~~

이것이 현재 코드 34번 줄의 핵심이며, 이 부분은 잘 작성했습니다.

---

## 8. 추천 구현

~~~python
def solution():
    n = int(input())
    arr = list(map(int, input().split()))

    if n == 1:
        return arr[0]

    dp = [0] * n

    dp[0] = arr[0]
    dp[1] = max(arr[0], arr[1])

    for i in range(2, n):
        dp[i] = max(dp[i - 1], dp[i - 2] + arr[i])

    return dp[n - 1]
~~~

문제에서 n이 항상 3 이상이라고 보장하더라도, n이 1일 때를 처리해두면 코드의 기본 상태가 더 안전합니다.

## 9. 예외와 반례를 생각하는 방법

반례를 찾을 때는 단순히 랜덤 숫자를 넣기보다, 코드의 각 부분을 의심해야 합니다.

### 1단계: 입력의 최소 크기 확인

먼저 가장 작은 입력을 생각합니다.

~~~text
n = 1
~~~

이때 코드가 다음을 접근하는지 확인합니다.

~~~python
arr[1]
~~~

n이 1이면 존재하지 않는 인덱스이므로 IndexError가 발생합니다.

확인할 질문:

- n이 1일 때도 배열 접근이 가능한가?
- dp를 몇 개 만들고 있는가?
- 반복문이 실행되지 않아도 정답이 나오는가?

### 2단계: 초기값을 의심하기

현재 코드에는 다음 초기화가 있습니다.

~~~python
dp = [arr[0], arr[1]]
~~~

초기값이 단순히 원소값을 복사한 것이 아니라, 상태 정의에 맞는 값인지 확인해야 합니다.

dp[1]의 의미가 “0번부터 1번까지 고려한 최댓값”이라면:

~~~python
dp[1] = max(arr[0], arr[1])
~~~

이어야 합니다.

확인할 질문:

- dp[0]은 무엇을 의미하는가?
- dp[1]은 무엇을 의미하는가?
- 그 상태에서 가능한 선택을 모두 반영했는가?

### 3단계: 선택이 다시 등장하는 입력 만들기

초기값의 오류는 다음 상태에서 바로 드러나지 않을 수 있습니다.

따라서 초기 상태에서 놓친 값이 나중에 다시 선택될 수 있도록 입력을 구성합니다.

현재 코드가 arr[0]을 dp[1]에서 놓치므로:

- arr[0]은 크게
- arr[1]은 작게
- arr[2]는 arr[0]을 선택해도 부담이 없게
- arr[3]은 크게

만듭니다.

~~~text
100 0 0 200
~~~

이렇게 하면 정답은 arr[0] + arr[3]이 됩니다.

### 4단계: 경계값과 극단값 넣기

다음 입력도 항상 확인하는 것이 좋습니다.

~~~text
n = 1
~~~

~~~text
모든 값이 0
~~~

~~~text
한쪽 끝의 값만 매우 큼
~~~

~~~text
양 끝 값이 모두 큼
~~~

~~~text
서로 번갈아 큰 값과 작은 값
~~~

예를 들어:

~~~text
100 1 100 1 100
~~~

또는:

~~~text
1 100 1 100 1
~~~

이런 입력은 인접 선택 조건과 DP 상태 정의를 확인하기 좋습니다.

### 5단계: 점화식의 두 선택을 각각 테스트하기

점화식은 다음 두 경우를 비교합니다.

~~~python
max(dp[i - 1], dp[i - 2] + arr[i])
~~~

따라서 각각의 경우가 정답이 되는 입력을 따로 만들어야 합니다.

현재 창고를 건너뛰는 것이 좋은 경우:

~~~text
5 100 5
~~~

현재 창고를 선택하는 것이 좋은 경우:

~~~text
5 1 100
~~~

두 경우 모두 코드가 처리하는지 확인합니다.

## 11. 복잡도

n을 창고의 개수라고 하겠습니다.

각 창고를 한 번씩 계산하므로:

~~~text
시간 복잡도: O(n)
~~~

dp 배열에 각 위치의 결과를 저장하므로:

~~~text
공간 복잡도: O(n)
~~~

현재 문제의 입력 크기에서는 충분히 효율적입니다.

---

## 12. 공간을 줄이는 선택적 개선

dp[i]를 계산할 때 필요한 값은 바로 이전 두 상태뿐입니다.

따라서 전체 dp 배열을 만들지 않고 변수 두 개만 사용할 수 있습니다.

~~~python
def solution():
    n = int(input())
    arr = list(map(int, input().split()))

    if n == 1:
        return arr[0]

    prev2 = arr[0]
    prev1 = max(arr[0], arr[1])

    for value in arr[2:]:
        current = max(prev1, prev2 + value)
        prev2, prev1 = prev1, current

    return prev1
~~~

이 경우:

~~~text
시간 복잡도: O(n)
공간 복잡도: O(1)
~~~

다만 DP를 처음 공부하는 단계에서는 전체 dp 배열을 사용해 상태 변화를 직접 확인하는 편이 이해에 더 좋습니다.

## 13. 주석에서 보완할 점

현재 주석:

~~~text
f(n) = max(f(n-1), f(n - 2))
~~~

에는 현재 창고의 식량인 arr[n]이 빠져 있습니다.

정확한 점화식은 다음입니다.

~~~text
f(n) = max(f(n - 1), f(n - 2) + arr[n])
~~~

또한 “경우의 수”라는 표현보다 “최대 식량의 양”이라는 표현이 정확합니다.

이 문제는 가능한 선택 방법의 개수를 세는 문제가 아니라, 선택 결과 중 최댓값을 구하는 문제입니다.

---

## 14. 문제에서 읽어야 할 신호

다음 표현이 보이면 DP를 생각할 수 있습니다.

- 인접한 원소를 동시에 선택할 수 없다.
- 선택하거나 선택하지 않을 수 있다.
- 최댓값을 구한다.
- 이전 위치까지의 최적 결과를 재사용할 수 있다.

특히 현재 위치 i에서:

~~~text
i를 선택하면 i - 1은 선택할 수 없음
i를 선택하지 않으면 i - 1까지의 결과를 사용
~~~

라는 구조가 점화식으로 바로 연결됩니다.
