작성하신 코드는 BFS의 핵심 원리와 collections.deque 사용, 방향 벡터 설정, 큐 삽입 시점의 방문 처리까지 문제의 정답을 맞히기에 부족함이 없는 훌륭한 코드입니다!

다만, 코딩 테스트 실전 관점에서 더 높은 효율성, 깔끔한 파이썬스러운(Pythonic) 스타일, 그리고 DFS/BFS 문제 해결 전략 측면에서 몇 가지 피드백과 팁을 코딩 테스트 선생님의 시선으로 정리해 드리겠습니다.

### 📌 잘하신 점 (칭찬 포인트)

1.  collections.deque 활용: list.pop(0) (O(N)) 대신 deque.popleft() (O(1))를 정확히 사용하여 탐색 속도를 최적화했습니다.
2.  큐 삽입 직후 방문 처리: visited.add((nr, nc)) 를 큐에 넣는 순간 처리해 주셨습니다. (많은 초보자분들이 큐에서 pop 할 때 방문 처리를 하다가 중복 큐 삽입으로 메모리 초과를 겪는데, 이 실수를 정확히 피하셨습니다!)
3.  방향 벡터( moves ) 모듈화: 상하좌우 탐색을 위해 델타 좌표 배열을 깔끔하게 정의했습니다.

### 💡 생각해 봐야 할 점 & 개선할 부문 (Feedback)

#### 1. set() vs 원본 배열 수정 (또는 2차원 bool 리스트)

• 현재 코드: visited = set() 후 (nr, nc) 튜플 추가
• 개선 아이디어:
• 이 문제처럼 단순히 "얼음 틀 구멍(0)을 방문했는가?"만 확인하면 되고 원본 맵을 보존할 필요가 없다면, 방문한 칸을 maps[nr][nc] = 1 로 직접 바꿔버리는 것이 가장 좋습니다.
• 이렇게 하면 visited 집합이 아예 필요 없어지므로 **공간 복잡도가 O(1)**로 줄어들고, 튜플 생성 및 해시 연산 오버헤드도 사라집니다.

#### 2. 입력 받기 (Pythonic Input Handling)

• 현재 코드: maps = [[int(x) for x in input() if x != "\n"] for _ in range(N)]
• 개선 아이디어:
• sys.stdin.readline 의 개행문자( \n ) 처리는 rstrip() 을 활용하면 훨씬 직관적이고 깔끔합니다.
• maps = [list(map(int, input().rstrip())) for _ in range(N)]

#### 3. BFS vs DFS 선택 기준

• BFS (현재 방식): 최단 거리/최단 경로 문제에 필수적입니다.
• DFS (재귀 방식): 단순 연결 요소(덩어리/컴포넌트) 개수 세기 문제는 DFS로 풀면 코드가 훨씬 짧아지고 구현 속도가 빠릅니다. (아래 더 나은 코드 참고)

### 🛠️ 더 나은 코드 제안

#### [방법 1] 메모리/속도를 최적화한 BFS (원본 배열 수정)

```py
    import collections
    import os
    import sys

    if os.path.exists(os.path.join(os.path.dirname(__file__), "input.txt")):
        sys.stdin = open(os.path.join(os.path.dirname(__file__), "input.txt"), "r")

    input = sys.stdin.readline


    def solution():
        N, M = map(int, input().split())
        # rstrip()으로 개행 제거 후 바로 int 리스트로 변환
        maps = [list(map(int, input().rstrip())) for _ in range(N)]

        dr = [-1, 1, 0, 0]
        dc = [0, 0, -1, 1]

        def bfs(start_r, start_c):
            queue = collections.deque([(start_r, start_c)])
            maps[start_r][start_c] = 1  # 시작점 방문 처리 (1로 변경)

            while queue:
                r, c = queue.popleft()
                for i in range(4):
                    nr, nc = r + dr[i], c + dc[i]
                    if 0 <= nr < N and 0 <= nc < M and maps[nr][nc] == 0:
                        maps[nr][nc] = 1  # 방문 처리 후 큐 삽입
                        queue.append((nr, nc))

        result = 0
        for i in range(N):
            for j in range(M):
                if maps[i][j] == 0:
                    bfs(i, j)
                    result += 1

        return result


    if __name__ == "__main__":
        print(solution())
    ──────

#### [방법 2] 재귀 DFS로 구현 (코딩테스트 실전 속도전추천)

    import sys

    # 파이썬 재귀 깊이 제한 해제 (필수)
    sys.setrecursionlimit(10**6)


    def solution():
        N, M = map(int, input().split())
        maps = [list(map(int, input().rstrip())) for _ in range(N)]

        def dfs(r, c):
            # 경계면 벗어나면 바로 종료
            if r < 0 or r >= N or c < 0 or c >= M:
                return False

            # 아직 방문 안 한 구멍(0)이라면
            if maps[r][c] == 0:
                maps[r][c] = 1  # 방문 처리

                # 상, 하, 좌, 우 재귀 호출
                dfs(r - 1, c)
                dfs(r + 1, c)
                dfs(r, c - 1)
                dfs(r, c + 1)
                return True

            return False

        result = 0
        for i in range(N):
            for j in range(M):
                # 현재 위치에서 DFS 수행 후 새로운 아이스크림 덩어리면 +1
                if dfs(i, j):
                    result += 1

        return result
    ──────
```

### 📝 코딩테스트 선생님의 3줄 요약 체크리스트

1. 방문 배열 대신 원본 맵 활용: 특별히 원본 배열을 지켜야 하는 조건이 없다면 맵 자체를 수정( 0 -> 1 )해서 메모리를 아끼자.
2. 입력 문자열 정제: list(map(int, input().rstrip())) 공식을 기억해두자.
3. BFS vs DFS 판단 기준:
   • 최단 경로/최소 이동 횟수 ➡️ BFS ( deque )
   • 영역 개수 구하기 / Flood Fill ➡️ DFS (재귀)가 코딩 속도가 훨씬 빠르다.
