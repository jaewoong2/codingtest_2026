# 이코테 곱하기 혹은 더하기 첨삭

## 총평

- **판정: 조건부 정답**
- 현재 최신 코드의 반복 범위가 `string[1:]`이라면, 핵심 그리디 알고리즘은 정답입니다.
- 다만 `0` 또는 `1`을 판단하는 조건이 표준 형태와 달라서, 왜 맞는지 설명하기 어렵고 수정 과정에서 실수하기 쉽습니다.
- 현재 코드는 앞자리 0을 `int`로 제거하는 방식에 의존하고 있으므로, 입력을 문자열 그대로 처리하는 방식으로 정리하는 것이 좋습니다.

## 문제 핵심

숫자로 이루어진 문자열의 숫자 사이에 `+` 또는 `*`를 넣어 만들 수 있는 최댓값을 구하는 문제입니다.

현재 누적 결과를 `result`, 다음 숫자를 `number`라고 하면 다음 조건을 사용합니다.

```python
if result <= 1 or number <= 1:
    result += number
else:
    result *= number
```

중요한 점은 **다음 숫자만 보는 것이 아니라 현재 누적 결과도 함께 봐야 한다는 것**입니다.

## 현재 풀이의 접근법

현재 코드는 숫자 문자열을 숫자 리스트로 바꾼 뒤 첫 번째 숫자를 초기값으로 사용하고, 두 번째 숫자부터 순회합니다.

```python
result = string[0]

for number in string[1:]:
    if number == 0 or number == 1 or result == 1:
        result += number
    else:
        result *= number
```

왼쪽부터 현재 결과를 갱신하는 구조와 `string[1:]`으로 첫 번째 숫자를 다시 처리하지 않는 점은 올바릅니다.

## 정확성 검토

### 현재 조건이 헷갈리는 이유

현재 조건:

```python
number == 0 or number == 1 or result == 1
```

표준 조건:

```python
result <= 1 or number <= 1
```

현재 코드는 `result == 0`을 직접 확인하지 않습니다.

다만 현재 입력 처리에서:

```python
str(int(str(input())))
```

앞자리 0이 제거됩니다. 그래서 첫 번째 `result`가 0인 경우는 입력이 전부 0인 경우뿐이고, 그때는 처리할 다음 숫자가 없습니다. 이 구조 때문에 현재 코드에서 바로 오답이 되는 반례는 확인되지 않았습니다.

하지만 이 조건은 입력 처리 방식에 의존하고 있습니다. 나중에 입력을 문자열 그대로 읽도록 바꾸면 `result == 0`도 반드시 처리해야 합니다.

예를 들어 누적 결과가 0이고 다음 숫자가 2라면:

```text
0 + 2 = 2
0 * 2 = 0
```

더하기가 정답입니다.

따라서 `result == 1`처럼 특정 값만 적기보다 `result <= 1`로 작성하는 것이 안전합니다.

### 실행으로 확인한 테스트

현재 코드에 각 입력을 넣어 다음 결과를 확인했습니다.

| 입력 | 기대 출력 | 현재 출력 |
|---|---:|---:|
| `12` | 3 | 3 |
| `102` | 3 | 3 |
| `02984` | 576 | 576 |
| `123` | 9 | 9 |

현재 코드의 핵심 알고리즘은 이 테스트들에서 올바르게 동작합니다.

### 반복 범위는 반드시 `string[1:]`이어야 함

현재 파일처럼 다음과 같아야 합니다.

```python
result = string[0]
for number in string[1:]:
```

만약 다음처럼 바뀌면 첫 번째 숫자를 두 번 처리해서 오답입니다.

```python
result = string[0]
for number in string:
```

예를 들어 입력 `1`에서 기대값은 1이지만, 첫 번째 숫자를 다시 더하면 2가 됩니다.

## 그리디 조건이 성립하는 이유

현재 결과를 `a`, 다음 숫자를 `b`라고 하겠습니다. 두 값은 0 이상의 정수입니다.

### `a <= 1` 또는 `b <= 1`

이 경우 더하기가 곱하기보다 작지 않습니다.

```text
a = 0: 0 + b >= 0 * b
a = 1: 1 + b >= 1 * b
b = 0: a + 0 >= a * 0
b = 1: a + 1 >= a * 1
```

따라서 더하기를 선택합니다.

### `a >= 2`이고 `b >= 2`

이 경우에는 곱셈이 더하기보다 작지 않습니다.

```text
a * b >= a + b
```

`2`와 `2`에서는 두 결과가 같고, 그 외에는 곱셈이 더 큽니다. 따라서 곱셈을 선택해도 손해가 없습니다.

## 추천 구현

입력을 정수로 바꾸지 말고 문자열 그대로 읽으면 조건의 의미가 더 명확해집니다.

```python
def solution():
    digits = input().strip()
    result = int(digits[0])

    for digit in digits[1:]:
        number = int(digit)

        if result <= 1 or number <= 1:
            result += number
        else:
            result *= number

    return result
```

이 구현은 현재 풀이의 아이디어를 그대로 유지하면서 조건과 입력 처리를 명확하게 만든 것입니다.

## 복잡도

문자열 길이를 `N`이라고 하겠습니다.

- 각 숫자를 한 번씩 확인하므로 시간 복잡도는 `O(N)`입니다.
- 현재 리스트를 만드는 방식은 `O(N)`의 추가 공간을 사용합니다.
- 추천 구현은 입력 문자열을 제외하면 추가 공간 `O(1)`입니다.

## 필수 수정

정답성 관점에서 현재 최신 코드는 동작할 가능성이 높지만, 다음 형태로 조건을 바꾸는 것을 권장합니다.

```python
if result <= 1 or number <= 1:
```

그리고 반복 범위가 반드시 `string[1:]`인지 확인해야 합니다.

## 선택적 개선

- `string`보다 `digits`가 숫자 문자열이라는 의미를 잘 드러냅니다.
- `str(int(str(input())))`는 앞자리 0을 제거하므로 불필요합니다.
- `input.txt`가 존재하면 표준 입력보다 해당 파일을 우선해서 읽으므로, 제출 전에는 표준 입력으로도 동작하는지 확인하세요.

## 이 문제에서 읽어야 할 신호

- 숫자를 왼쪽부터 순서대로 처리한다.
- 매 단계에서 더하기와 곱하기 중 하나를 선택한다.
- 0 또는 1이 포함된 연산에서는 곱셈이 결과를 키우지 못한다.
- 누적 결과가 0 또는 1이어도 곱셈보다 덧셈이 유리하다.

이 문제의 핵심은 “현재 숫자가 0 또는 1인가?”가 아니라 **현재 누적 결과와 다음 숫자를 함께 비교하는 것**입니다.
