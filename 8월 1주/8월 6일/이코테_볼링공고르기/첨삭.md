# 이코테 볼링공 고르기 첨삭

## 총평

- **판정: 정답**
- 현재 실행되는 `solution2()`는 같은 무게의 공을 제외하고, 서로 다른 무게의 공을 고르는 경우의 수를 정확히 계산합니다.
- 샘플 입력의 실행 결과는 `25`였고, 작은 무작위 입력을 완전탐색 결과와 비교한 검증도 통과했습니다.

## 문제 핵심

공 `N`개 중 2개를 고르되, 두 공의 무게가 같지 않도록 하는 경우의 수를 구하는 문제입니다.

공의 순서는 중요하지 않습니다. 예를 들어 A와 B를 고르는 것과 B와 A를 고르는 것은 같은 경우입니다.

샘플:

```text
N = 8
무게 = 1 5 4 3 2 4 5 2
```

전체 두 공 선택은 `8C2 = 28`가지입니다.

- 무게 2인 공 2개를 고르는 경우 1가지 제외
- 무게 4인 공 2개를 고르는 경우 1가지 제외
- 무게 5인 공 2개를 고르는 경우 1가지 제외

따라서 `28 - 3 = 25`입니다.

## 현재 접근법

현재 `solution2()`는 무게별 공의 개수를 센 뒤, 각 무게와 더 큰 무게의 공을 짝짓습니다.

```python
balls = [0 for _ in range(m + 1)]

for ball in arr:
    balls[ball] += 1
```

예를 들어 샘플의 개수는 다음과 같습니다.

```text
무게 1: 1개
무게 2: 2개
무게 3: 1개
무게 4: 2개
무게 5: 2개
```

이후의 핵심 코드입니다.

```python
choiceable = n

for i in range(m + 1):
    choiceable = choiceable - balls[i]
    result += balls[i] * choiceable
```

`choiceable`은 현재 무게보다 **큰 무게를 가진 공의 개수**입니다.

예를 들어 무게 2인 공이 2개이고, 무게 3 이상인 공이 5개라면:

```text
무게 2 공 선택: 2가지
상대 공 선택: 5가지
경우의 수: 2 * 5 = 10
```

이렇게 계산하면 두 공의 무게가 자동으로 달라집니다. 같은 무게의 공은 `choiceable`에 포함하지 않기 때문입니다.

## 예시 추적

샘플 입력에서 각 무게를 처리하면 다음과 같습니다.

| 현재 무게 | 현재 무게 공 수 | 더 큰 무게 공 수 | 추가 경우의 수 | 누적 결과 |
|---:|---:|---:|---:|---:|
| 1 | 1 | 7 | `1 × 7` | 7 |
| 2 | 2 | 5 | `2 × 5` | 17 |
| 3 | 1 | 4 | `1 × 4` | 21 |
| 4 | 2 | 2 | `2 × 2` | 25 |
| 5 | 2 | 0 | `2 × 0` | 25 |

각 유효한 쌍은 항상 더 가벼운 공의 무게를 기준으로 딱 한 번만 계산됩니다. 따라서 중복 계산도 없습니다.

## 정확성

현재 코드가 맞는 이유는 모든 공의 쌍을 다음 두 종류로 나눌 수 있기 때문입니다.

1. 두 공의 무게가 같은 쌍
2. 두 공의 무게가 다른 쌍

문제에서 필요한 것은 2번입니다.

현재 코드는 무게 `i`인 공 하나를 고른 뒤, 무게 `i`보다 큰 공만 선택합니다.

- 같은 무게는 제외됩니다.
- 더 작은 무게와의 쌍은 이전 반복에서 이미 계산됩니다.
- 더 큰 무게와의 쌍은 현재 반복에서 계산됩니다.

따라서 서로 다른 무게의 모든 쌍을 정확히 한 번씩 셉니다.

## 복잡도

`N`을 공의 개수, `M`을 가능한 최대 무게라고 하겠습니다.

현재 실행되는 `solution2()`의 복잡도는 다음과 같습니다.

- 공 개수 세기: `O(N)`
- 무게 종류 순회: `O(M)`
- 전체 시간 복잡도: `O(N + M)`
- `balls` 배열 추가 공간: `O(M)`

완전탐색의 `O(N²)`보다 효율적인 풀이입니다.

## 필수 수정

현재 `__main__`에서 실행하는 `solution2()`에는 필수 수정이 없습니다.

다만 다음처럼 `balls[1:]`만 순회하면 존재하지 않는 무게 0을 굳이 확인하지 않아 의도가 더 분명합니다.

```python
for count in balls[1:]:
    choiceable -= count
    result += count * choiceable
```

현재 코드도 `balls[0]`이 항상 0이므로 결과에는 영향을 주지 않습니다.

## 사용하지 않는 `solution()`에 대한 피드백

아래 함수는 현재 실행되지 않지만, 모든 조합을 리스트로 만들어 비효율적입니다.

```python
result = len([x for x in combinations(range(n), 2)])
```

`N`개 중 2개를 고르는 개수는 다음 공식으로 바로 구할 수 있습니다.

```python
result = n * (n - 1) // 2
```

또한 `combinations(...)`의 결과를 리스트로 변환하면 조합 개수만큼 메모리를 추가로 사용합니다. 이 문제에서는 무게별 개수만 세면 되므로 `solution()`은 삭제하거나 참고용으로만 남겨 두는 편이 좋습니다.

## 선택적 개선

제출 코드에서는 로컬 테스트용 입력 전환 코드를 제거하는 편이 안전합니다.

```python
if os.path.exists(os.path.join(os.path.dirname(__file__), "input.txt")):
    sys.stdin = open(os.path.join(os.path.dirname(__file__), "input.txt"), "r")
```

같은 폴더에 `input.txt`가 있으면 표준 입력 대신 그 파일을 읽기 때문입니다. 알고리즘과는 무관하지만, 제출 시 오래된 입력 파일을 읽는 실수를 방지할 수 있습니다.

## 이 문제에서 읽어야 할 신호

- “두 개를 고른다” → 전체 쌍은 `N²` 또는 `N개 중 2개`
- “무게가 달라야 한다” → 같은 무게 조합을 제외하거나 무게별로 나누기
- 무게의 범위 `M`이 작다 → 무게별 빈도 배열 사용
- 같은 종류의 값이 반복된다 → 실제 원소 하나씩보다 개수로 묶어 계산

## 다음 문제를 위한 체크포인트

1. 전체 경우의 수를 먼저 계산한다.
2. 조건을 만족하지 않는 경우를 빼도 되는지 확인한다.
3. 값의 종류 범위가 작으면 빈도 배열을 생각한다.
4. 각 쌍이 정확히 한 번만 계산되는 기준을 정한다.
5. 모든 쌍을 직접 만들 필요가 있는지 확인한다.

이번 풀이의 가장 좋은 점은 `N`개의 공을 직접 서로 비교하지 않고, **무게별 개수로 묶어서 계산한 것**입니다. 다음에는 사용하지 않는 완전탐색 함수는 정리하고, 현재 풀이 하나만 남겨도 충분합니다.
