## 총평

- 판정: 조건부 정답
- 핵심 이유: 진입 차수를 계산하고, 진입 차수가 0인 정점을 큐에 넣은 뒤 간선을 제거하는 Kahn 방식의 위상 정렬을 올바르게 구현했다.
- 단, 사이클이 있는 입력에서 결과 길이를 확인하지 않으며, 문제의 출력 형식이 리스트가 아니라면 출력 부분을 수정해야 한다.

## 현재 접근법

1. `indegrees[b]`에 각 정점으로 들어오는 간선 수를 저장한다.
2. 진입 차수가 0인 정점을 큐에 넣는다.
3. 큐에서 정점을 꺼내 결과에 추가한다.
4. 해당 정점에서 나가는 간선을 제거하면서 진입 차수가 0이 된 정점을 큐에 추가한다.

이 흐름은 위상 정렬의 표준적인 방식이다.

## 정확성 검토

### 잘한 점

- 25행에서 도착 정점의 진입 차수를 증가시킨다.
- 31~33행에서 진입 차수가 0인 모든 정점을 초기 큐에 넣는다.
- 39~43행에서 간선을 제거한 뒤 정확히 0이 된 정점만 큐에 넣는다.
- 모든 정점을 인접 리스트에 포함할 수 있도록 `v + 1` 크기의 리스트를 만든 점이 안전하다.

현재 입력으로 실행한 실제 결과는 다음과 같다.

```text
[1, 2, 5, 3, 6, 4, 7]
```

이 순서는 모든 간선 방향을 만족하므로 올바른 위상 순서다. 위상 정렬은 여러 답이 존재할 수 있으므로 결과가 하나의 정답 예시와 다르다고 틀린 것은 아니다.

### 필수 확인: 사이클 처리

사이클이 있으면 진입 차수가 0인 정점이 더 이상 생기지 않아 큐가 먼저 비워진다. 현재 코드는 일부 정점만 `response`에 넣고 그대로 반환한다.

예를 들어:

```text
3 3
1 2
2 3
3 1
```

위 그래프는 위상 정렬이 불가능하지만 현재 로직은 빈 리스트를 반환한다. 사이클을 판정해야 하는 문제라면 반복문 뒤에 다음 검사가 필요하다.

```python
if len(response) != v:
    # 사이클 존재 처리
```

문제에서 DAG임을 보장한다면 이 검사는 선택 사항이다.

### 출력 형식

현재 50행은 리스트를 그대로 출력하므로 다음처럼 나온다.

```text
[1, 2, 5, 3, 6, 4, 7]
```

문제에서 정점을 공백으로 출력하라고 했다면 리스트가 아니라 공백 구분 형식으로 출력해야 한다. 단, 연습용 함수의 반환값을 확인하는 목적이면 현재 형식도 괜찮다.

## 복잡도

`V`를 정점 수, `E`를 간선 수라고 하면 각 정점과 간선을 최대 한 번씩 처리하므로 시간 복잡도는 `O(V + E)`이다. 인접 리스트, 진입 차수 배열, 큐, 결과 배열을 사용하므로 공간 복잡도도 `O(V + E)`이다.

## 필수 수정

1. 문제에서 사이클을 허용하거나 감지해야 한다면 `len(response) != v`를 검사한다.
2. 출력 요구사항이 있다면 리스트 출력 대신 문제 형식에 맞춰 출력한다.

## 선택적 개선

- `deque([])`는 `deque()`로 쓸 수 있다.
- `while len(queue) > 0`은 `while queue`로 줄일 수 있다.
- 사용하지 않는 `import dis`는 제거해도 된다.

## 이 문제에서 읽어야 할 신호

“선행 작업”, “먼저 해야 하는 작업”, “순서” 같은 조건과 `A → B` 형태의 방향 관계는 위상 정렬을 떠올리게 한다. 진입 차수가 0이라는 것은 선행 조건이 모두 해결된 상태라는 의미다.
