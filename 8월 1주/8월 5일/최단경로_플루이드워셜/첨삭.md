## 총평

- 판정: 조건부 정답
- 핵심 이유: 플루이드–워셜의 핵심인 `k → i → j` 순서의 3중 반복문과 방향 간선 초기화는 올바르다. 다만 현재 실행 결과에는 리스트 문법과 `None`이 섞여 나오고, 고립 정점이나 중복 간선이 있는 입력에서는 문제가 생길 수 있다.

## 현재 접근법

`distances[i][j]`를 정점 `i`에서 `j`까지의 현재 최단 거리로 두고, 대각선은 0으로 초기화한다. 이후 `k`를 중간 정점으로 허용하면서 다음 값을 갱신한다.

```python
distances[i][j] = min(
    distances[i][j],
    distances[i][k] + distances[k][j]
)
```

## 잘한 점

- 24행에서 `k`를 가장 바깥 반복문으로 둔 점이 정확하다.
- 18~19행에서 자기 자신까지의 거리를 0으로 초기화했다.
- 47행에서 `graphs[a].append((b, c))`만 사용해 입력을 방향 그래프로 처리했다.
- 현재 입력의 거리 계산값 자체는 올바르다.

## 정확성 및 반례

### 1. 출력 형식이 잘못될 가능성이 큼

현재 입력으로 실행한 실제 출력은 다음과 같다.

```text
[0, 4, 8, 6]
[3, 0, 7, 9]
[5, 9, 0, 4]
[7, 11, 2, 0]
None
```

51행에서 리스트를 그대로 출력하기 때문에 대괄호와 쉼표가 포함된다. 또한 56~57행에서 `solution()`의 반환값을 출력하지만 `solution()`은 반환문이 없어서 마지막에 `None`이 출력된다.

일반적인 최단거리 행렬 문제라면 보통 각 행을 공백으로 구분해 출력하고, 도달할 수 없는 곳은 문제에서 요구하는 값으로 바꿔 출력해야 한다. `solution()` 안에서 출력할 것인지, 결과를 반환해서 바깥에서 출력할 것인지 한 방식으로 통일해야 한다.

### 2. 고립된 정점에서 `KeyError` 발생

현재 `graphs`는 간선에 등장한 정점만 키로 만든다. 예를 들어 다음처럼 3번 정점이 어떤 간선에도 등장하지 않으면:

```text
3 1
1 2 1
```

`fluid()`의 `graphs[3]`에서 `KeyError`가 발생한다. 실제 실행에서도 `KeyError: 3`이 확인되었다.

처음부터 다음처럼 모든 정점의 인접 리스트를 준비하는 편이 안전하다.

```python
graphs = [[] for _ in range(n + 1)]
```

또는 순회 시 `graphs.get(i, [])`를 사용할 수 있다.

### 3. 중복 간선 처리

현재 22행은 같은 `i -> node` 간선이 여러 번 나오면 마지막 입력으로 덮어쓴다. 중복 간선이 허용되는 문제라면 더 작은 값을 보존해야 한다.

```python
distances[i][node] = min(distances[i][node], distance)
```

예를 들어 `1 -> 2`의 비용이 3과 10으로 두 번 주어지면 3을 사용해야 한다.

### 4. 무한대 값

`int(1e9)`가 가능한 최단 거리보다 작을 수 있는 제약이라면 오답이 된다. 제약을 확인하고 충분히 큰 값이나 `float("inf")`를 사용해야 한다.

## 복잡도

`N`을 정점 수라고 하면 3중 반복문 때문에 시간 복잡도는 `O(N^3)`이다. 거리 행렬의 공간 복잡도는 `O(N^2)`이다. 모든 정점 쌍의 최단 거리를 구하는 플루이드–워셜의 일반적인 복잡도와 일치한다.

## 필수 수정

1. `solution()`과 바깥의 `print(result)` 중 출력 방식을 하나로 통일한다.
2. 문제의 출력 형식에 맞게 리스트가 아닌 공백 구분 형식 등으로 출력한다.
3. 모든 정점의 인접 리스트를 준비하거나 `graphs.get()`을 사용한다.
4. 중복 간선이 가능하면 직접 거리 초기화 시 최솟값을 보존한다.

## 선택적 개선

- `fluid`보다 `floyd_warshall`처럼 알고리즘 이름을 드러내는 함수명이 읽기 쉽다.
- 인접 리스트를 거치지 않고 `distances[a][b]`를 직접 초기화하면 플루이드–워셜의 구조가 더 간결해질 수 있다.
- 무한대 값은 `float("inf")`로 두면 큰 상수의 의미를 고민하지 않아도 된다.

## 이 문제에서 읽어야 할 신호

“모든 정점에서 모든 정점까지의 최단 거리”를 한 번에 구해야 하고 정점 수가 충분히 작다면, 중간 정점을 하나씩 허용하는 플루이드–워셜을 고려할 수 있다. 방향 그래프라면 간선 `a -> b`만 저장하고 역방향을 임의로 추가하지 않는다.
