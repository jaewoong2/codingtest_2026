# 다익스트라 풀이 첨삭

## 총평

- 판정: 조건부 정답
- 핵심 이유: 우선순위 큐에서 가장 짧은 거리를 꺼내고, 더 짧은 거리만 다시 넣는 다익스트라의 핵심 로직은 올바르다. 다만 현재 입력을 무방향 그래프로 처리하고 있으며, 시작 정점이 어떤 간선에도 연결되지 않은 경우에는 `KeyError`가 발생한다.
- 저장소에 문제 원문과 출력 조건이 없어 그래프 방향과 출력 형식까지 포함한 최종 판정은 문제 조건에 따라 달라진다.

## 문제 핵심

현재 `input.txt` 형식은 `정점 수`, `간선 수`, `시작 정점`, 그리고 `a b c` 형태의 간선으로 보인다. 다익스트라는 모든 간선의 가중치가 음수가 아니어야 하며, 입력 간선이 `a -> b`인지 `a <-> b`인지가 중요하다.

## 현재 접근법

`distances`에 시작점에서 각 정점까지의 현재 최단 거리를 저장하고, `(거리, 정점)`을 최소 힙에 넣는다. 힙에서 꺼낸 값이 이미 갱신된 거리보다 크면 버리고, 인접 정점을 확인하면서 더 짧은 경로를 찾으면 힙에 다시 넣는 방식이다.

이 방식은 방문 배열 없이도 다음 조건으로 오래된 힙 원소를 걸러낼 수 있다.

```python
if distances[node] < value:
    continue
```

## 정확성 및 반례

### 잘한 점

- 힙 원소를 `(거리, 정점)` 순서로 저장해서 거리가 작은 정점부터 처리한다.
- 더 짧은 경로를 발견했을 때만 `distances`를 갱신하고 힙에 넣는다.
- 오래된 힙 원소를 건너뛰어 중복 삽입을 안전하게 처리한다.

### 필수 확인 1: 그래프 방향

현재 55행의 다음 코드 때문에 모든 간선이 양방향으로 추가된다.

```python
graphs[b].append((a, c))
```

문제가 방향 그래프라면 이 줄은 제거해야 한다. 예를 들어 다음 입력에서 간선은 `2 -> 1`뿐이다.

```text
3 1
1
2 1 1
```

방향 그래프의 기대 거리는 시작점 1에서 2로 갈 수 없으므로 `0, INF, INF`이다. 현재처럼 역방향 간선을 추가하면 1에서 2로 갈 수 있다고 판단하여 `0, 1, INF`가 된다.

반대로 문제가 무방향 그래프라면 현재처럼 양쪽 방향을 추가하는 것이 맞다.

### 필수 확인 2: 고립된 시작 정점

다음 입력처럼 시작점 1이 간선에 한 번도 등장하지 않으면 `graphs[1]`이 만들어지지 않는다.

```text
3 1
1
2 3 1
```

이 경우 코드 흐름상 시작점 1을 힙에서 꺼낸 뒤 `graphs[1]`을 조회하면서 `KeyError`가 발생한다. 실제 실행에서도 `KeyError: 1`이 확인되었다.

인접 리스트를 처음부터 다음처럼 만들면 모든 정점이 빈 리스트를 갖게 된다.

```python
graphs = [[] for _ in range(n + 1)]
```

### 필수 확인 3: 무한대 값과 출력 형식

`int(1e9)`를 무한대로 사용하면 실제 최단 거리가 10억 이상일 때 오답이 될 수 있다. 제약을 확인한 뒤 충분히 큰 정수를 사용하거나 `float("inf")`를 사용하는 편이 안전하다.

또한 현재 프로그램은 결과를 다음처럼 리스트 하나로 출력한다.

```text
[0, 2, 3, 1, 2, 4]
```

문제에서 정점별 거리를 줄마다 출력하도록 요구한다면 출력 부분도 수정해야 한다.

## 실행 확인

현재 `input.txt`로 실행했을 때의 실제 출력은 다음과 같았다.

```text
[0, 2, 3, 1, 2, 4]
```

이 결과는 현재 입력을 무방향 그래프로 해석하고 리스트 형태로 출력한 결과다. 샘플 하나가 통과해도 방향, 고립 정점, 큰 거리, 출력 형식까지 모두 맞는다는 뜻은 아니다.

## 복잡도

`V`를 정점 수, `E`를 간선 수라고 하면 인접 리스트와 이진 최소 힙을 사용하는 현재 방식의 시간 복잡도는 `O((V + E) log V)`이며, 공간 복잡도는 `O(V + E)`이다.

힙에서 오래된 원소를 제거하지 않고 건너뛰는 방식은 다익스트라에서 일반적으로 사용하는 구현이며, 최악 복잡도를 망치지 않는다.

## 필수 수정

1. 문제의 간선이 방향 그래프인지 확인한다.
2. 모든 정점에 대해 빈 인접 리스트를 먼저 만든다.
3. `1e9`가 제약을 항상 넘는지 확인하고 무한대 값을 정한다.
4. 문제에서 요구하는 출력 형식에 맞춰 리스트 출력 여부를 수정한다.

## 선택적 개선

- `while len(queue) > 0`은 `while queue`로 줄일 수 있다.
- `graphs`는 딕셔너리보다 `n + 1`개의 빈 리스트를 가진 리스트가 이 문제에서 더 직관적이다.
- `import heapq`는 함수 안보다 파일 위쪽에 두면 의존성이 눈에 잘 보인다.
- `int(1e9)`보다 `10**9` 또는 `float("inf")`가 의도를 더 분명하게 보여준다.

## 이 문제에서 읽어야 할 신호

“한 정점에서 다른 모든 정점까지의 최단 거리”와 “간선 가중치가 음수가 아님”이라는 조건은 다익스트라를 떠올리게 하는 신호다. 가중치가 모두 같다면 BFS, 음수 가중치가 가능하다면 다익스트라를 그대로 사용할 수 없다.

## 다음 문제를 위한 체크포인트

- 간선 입력이 방향인지 무방향인지 먼저 확인하기
- 고립된 정점과 도달할 수 없는 정점 처리하기
- 무한대 초기값이 가능한 최단 거리보다 충분히 큰지 확인하기
- 힙에서 꺼낸 값이 최신 거리인지 확인하기
- 반환값과 실제 출력 형식이 문제 요구사항과 같은지 확인하기
