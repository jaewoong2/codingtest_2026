# 최소 힙 직접 구현 첨삭

## 총평

- 판정: 현재 커스텀 힙은 오답
- 핵심 이유: `heappush`는 현재 올바르게 수정되었지만, `heappop`은 일부 크기에서 `None`을 반환하고 루트 교체 후 여러 단계 아래로 내려가지 못한다. 또한 현재 다익스트라는 커스텀 힙이 아니라 파이썬 내장 `heapq`를 사용한다.
- 샘플 실행은 `[0, 2, 3, 1, 2, 4]`가 나왔지만, 이는 커스텀 힙을 거치지 않은 결과다.

## 현재 접근법

`heap()` 안의 리스트를 완전 이진 트리로 보고, `heappush`에서는 새 원소를 위로 올리고 `heappop`에서는 루트 원소를 제거한 뒤 마지막 원소를 아래로 내리려는 구조다. 방향 자체는 맞다.

## 정확성 검토

### 1. `heappush`는 수정되어 현재 올바름

이전의 부모 인덱스 문제는 다음처럼 수정되어 해결되었다.

```python
parent_index = (child_index - 1) // 2
```

또한 부모와 현재 원소를 실제로 교환하고 있으므로 `heappush`는 `[3, 1, 2]`를 `[1, 3, 2]` 형태로 만드는 단계까지 잘 구현되었다.

### 2. `heappop`이 크기 3인 힙에서 `None` 반환

현재 51행의 조건 때문에 루트 제거 후 남은 힙의 크기가 2이면 아래 로직에 들어가지 않는다. 따라서 원래 원소가 3개였던 힙에서 `pop()`하면 75행의 반환문에 도달하지 못하고 `None`을 반환한다.

실제 테스트에서 `[3, 1, 2]`의 첫 `pop()` 결과가 `None`이었다.

루트 교체 후에는 힙 크기를 직접 비교하기보다, **왼쪽 자식이 존재하는 동안** 아래로 내려가야 한다.

### 3. `heappop`이 여러 단계 아래로 내려가지 못함

현재 코드는 한 번 교환한 뒤 61행의 조건에서 `parent_index`와 이전 `smallest_index`를 비교하게 된다. 새 위치의 자식들을 다시 선택하기 전에 반복이 끝날 수 있으므로, 힙 높이가 2 이상인 경우를 완전히 처리하지 못한다.

교환할 때마다 다음 순서로 다시 계산해야 한다.

```text
현재 위치의 왼쪽 자식이 있는지 확인
왼쪽·오른쪽 중 더 작은 자식 선택
현재 값이 더 작거나 같으면 종료
교환 후 현재 위치를 자식 위치로 이동
```

### 4. `heappop`의 자식 인덱스

현재 73행의 공식은 수정되어 올바르다. 부모 인덱스가 `p`일 때 자식은 다음이다.

```python
left = 2 * p + 1
right = 2 * p + 2
```

### 5. 오른쪽 자식이 없을 때를 처리해야 함

마지막 레벨에서는 왼쪽 자식만 존재할 수 있다. 따라서 작은 자식을 고를 때 오른쪽 인덱스가 리스트 길이 안에 있는지 먼저 확인해야 한다.

```text
왼쪽 자식이 없으면 종료
오른쪽 자식이 없으면 왼쪽 선택
둘 다 있으면 더 작은 자식 선택
```

### 6. 빈 힙의 반환값

빈 힙에서 `-1`을 반환하면 힙 원소가 정수일 때 실제 값과 충돌할 수 있다. `heapq.heappop`과 비슷하게 동작시키려면 `IndexError`를 발생시키거나, 별도 규칙으로 `None`을 사용해야 한다.

## 다익스트라와의 연결

현재 75행, 81행, 84행, 95행은 모두 내장 `heapq`를 사용한다. 커스텀 힙을 만들었지만 다익스트라에서는 아직 호출하지 않는다.

또 하나 주의할 점은 `heap()` 내부의 `queue`와 `dijkstra()` 내부의 `queue`가 서로 다른 리스트라는 것이다. 단순히 내장 `heapq` 호출만 커스텀 `heappush`, `heappop`으로 바꾸면 안 된다.

다음 중 한 가지 구조로 통일해야 한다.

1. 힙 클래스가 `self.queue`를 관리하고 `push`, `pop`, `empty`를 제공한다.
2. `heappush(queue, value)`, `heappop(queue)`처럼 외부 리스트를 함수 인자로 받는다.
3. 현재처럼 클로저를 유지한다면 `is_empty` 함수도 함께 반환하고, 다익스트라에서는 클로저 내부 큐만 사용한다.

개인적으로는 이 문제에서는 2번이 가장 단순하다.

## 최소 힙의 핵심 의사코드

### 삽입

```text
마지막에 원소 추가
현재 인덱스가 0이 아닐 동안:
    부모 인덱스 계산
    부모가 더 작거나 같으면 종료
    부모와 현재 원소 교환
    현재 인덱스를 부모로 이동
```

### 삭제

```text
루트 저장
마지막 원소를 루트로 이동하고 마지막 원소 삭제
현재 인덱스가 왼쪽 자식을 가지는 동안:
    왼쪽과 오른쪽 중 더 작은 자식 선택
    현재 원소가 더 작거나 같으면 종료
    현재 원소와 선택한 자식 교환
    현재 인덱스를 자식으로 이동
저장해 둔 루트 반환
```

## 복잡도

`N`을 힙에 들어 있는 원소 수라고 하면 삽입과 삭제 모두 트리 높이만큼 이동하므로 시간 복잡도는 `O(log N)`이다. 힙에 저장된 원소 수만큼 공간을 사용하므로 공간 복잡도는 `O(N)`이다.

## 필수 수정

1. `heappop`을 왼쪽 자식 존재 여부 기준의 반복문으로 일반화한다.
2. 교환할 때마다 자식 인덱스를 새로 계산한다.
3. 오른쪽 자식이 실제로 존재할 때만 비교한다.
4. 커스텀 힙과 다익스트라가 같은 큐를 사용하도록 구조를 통일한다.

## 이전 다익스트라 코드에서 이어지는 확인 사항

- `graphs[b].append((a, c))`는 무방향 그래프일 때만 유지한다.
- 딕셔너리 인접 리스트는 고립된 시작 정점에서 `KeyError`가 날 수 있으므로 모든 정점에 빈 리스트를 준비한다.
- `1e9`가 가능한 최단 거리보다 충분히 큰지 확인한다.
- 결과를 리스트로 출력해도 되는지 문제의 출력 형식을 확인한다.

## 다음 체크포인트

힙 구현에서는 매 연산마다 다음 불변식을 확인하면 된다.

> 모든 부모 노드의 값은 자식 노드의 값보다 작거나 같다.

`push`는 이 불변식을 위쪽 방향으로 복구하고, `pop`은 아래쪽 방향으로 복구한다. 구현 후에는 `[3, 1, 2]`, `[1, 2, 3]`, `[2, 1]`, 중복 값, 원소가 0개인 경우를 반드시 테스트하는 것이 좋다.
