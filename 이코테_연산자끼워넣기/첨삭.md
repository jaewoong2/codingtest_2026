# [이코테 / BOJ 14888] 연산자 끼워 넣기 풀이 첨삭

## 총평

- **판정**: **오답**
- **핵심 이유**: 각 연산자 배치의 결과를 계산하는 논리는 맞지만, 출력이 문제가 요구하는 두 줄이 아닌 파이썬 리스트 형식입니다. 또한 `N=11`이면 중복 연산자까지 구분한 `10! = 3,628,800`개의 순열을 먼저 메모리에 저장하므로 시간·메모리 제한을 넘길 위험이 큽니다.

## 문제 핵심

- `N`개의 수 사이에 주어진 개수만큼의 `+`, `-`, `*`, `/`를 하나씩 넣습니다.
- 연산자 우선순위를 무시하고 **앞에서부터 순서대로** 계산합니다.
- 음수 나눗셈은 절대값을 나눈 뒤 부호를 붙이는, 즉 **0을 향한 버림**입니다.
- 모든 연산자 배치의 결과 중 최댓값과 최솟값을 각각 한 줄에 출력합니다.
- 표준 제약은 `2 <= N <= 11`, `1 <= A_i <= 100`이고 연산자 개수의 합은 `N-1`입니다.

문제의 본질은 연산자 문자열을 모두 만드는 것이 아니라, **남아 있는 연산자의 개수를 상태로 두고 가능한 선택을 하나씩 시도하는 완전 탐색**입니다.

## 현재 접근법

1. 연산자 개수를 `+`, `-`, `*`, `/` 문자 리스트 `c`로 펼칩니다.
2. `permuation()`으로 연산자 인덱스의 모든 순열을 만들어 `candidates`에 저장합니다.
3. 같은 연산자들이 섞인 중복 순열은 문자열로 바꾼 `visited`로 제거합니다.
4. `calcuator()`가 수를 왼쪽부터 순서대로 계산하고, 결과의 최댓값과 최솟값을 갱신합니다.

완전 탐색을 선택한 것은 적절합니다. 다만 중복을 **만든 후에** 제거하고 있어 제약을 만족하지 못합니다.

## 정확성 및 반례

### 1. 계산 논리는 올바릅니다

- `calcuator()`는 앞의 결과에 다음 수를 계속 연산하므로 문제의 왼쪽에서 오른쪽 계산 규칙과 일치합니다.
- 음수에서 `//`를 바로 쓰지 않고, 절대값을 나눈 후 부호를 되돌려 0 방향 버림을 맞게 구현했습니다.
- 현재 최댓값·최솟값 초기값인 `-1e20`, `1e20`은 음수만 나오는 경우도 처리합니다.
- 연산자를 인덱스로 구분해 모든 순열을 만들기 때문에 효율적이지는 않지만 가능한 연산자 배치를 누락하지는 않습니다.

### 2. 출력 형식 반례

**반례 입력**

```text
2
1 2
0 1 0 0
```

**기대 출력**

```text
-1
-1
```

**코드의 실제 출력**

```text
[-1, -1]
```

결과값은 맞지만, `print(result)`가 대괄호와 쉼표를 포함한 파이썬 리스트를 한 줄로 출력합니다. 온라인 저지는 출력 형식을 정확히 비교하므로 오답 처리됩니다.

## 복잡도

`N`을 수의 개수, `K=N-1`을 연산자의 개수라고 하겠습니다.

- `permuation()`은 같은 문자인 연산자도 서로 다른 인덱스로 취급하여 `K!`개의 리스트를 만듭니다.
- 각 후보가 길이 `K`인 리스트이므로 **시간 복잡도는 `O(K * K!)`**, `candidates`의 **공간 복잡도도 `O(K * K!)`**입니다.
- `K=10`이면 완성 순열만 `3,628,800`개이고, 재귀 트리 전체에서는 약 `9,864,101`번의 호출이 발생합니다. 각 후보 리스트와 밖쪽 리스트의 참조까지 합치면 표준 메모리 제한에서 안전하지 않습니다.
- 중복 제거를 한 뒤의 실제 연산자 배치 수는 `K! / (p! q! m! d!)`입니다. `K=10`에서 최대는 개수가 `3, 3, 2, 2`로 분산될 때의 `25,200`개입니다.

남은 개수만 조절하며 DFS하면 중복 배치를 처음부터 만들지 않습니다. 이때 시간은 서로 다른 연산자 배치 수에 비례하고, 재귀 스택은 최대 `N`단계이므로 추가 공간은 `O(N)`입니다. 재귀 깊이는 최대 10이라 파이썬 재귀 한도에도 문제가 없습니다.

## 필수 수정

### 1. 결과를 두 줄로 출력하기

```python
result = solution()
print(result[0])
print(result[1])
```

### 2. 연산자 순열을 저장하지 말고, 남은 개수로 DFS하기

현재 코드의 핵심 의도인 “모든 연산자 순서를 시도한다”는 유지하되, 순서 전체를 선생성하지 않아야 합니다.

```python
def solution():
    n = int(input())
    numbers = list(map(int, input().split()))
    operators = list(map(int, input().split()))

    maximum = -int(1e20)
    minimum = int(1e20)

    def dfs(index, total):
        nonlocal maximum, minimum

        if index == n:
            maximum = max(maximum, total)
            minimum = min(minimum, total)
            return

        next_number = numbers[index]

        if operators[0] > 0:
            operators[0] -= 1
            dfs(index + 1, total + next_number)
            operators[0] += 1

        if operators[1] > 0:
            operators[1] -= 1
            dfs(index + 1, total - next_number)
            operators[1] += 1

        if operators[2] > 0:
            operators[2] -= 1
            dfs(index + 1, total * next_number)
            operators[2] += 1

        if operators[3] > 0:
            operators[3] -= 1
            if total < 0:
                divided = -(-total // next_number)
            else:
                divided = total // next_number
            dfs(index + 1, divided)
            operators[3] += 1

    dfs(1, numbers[0])
    return maximum, minimum
```

각 분기에서 연산자 개수를 하나 줄였다가 재귀호출 후 되돌리는 것이 핵심입니다. 이 복원 과정 덕분에 다른 분기가 원래의 연산자 개수를 그대로 사용할 수 있습니다.

## 선택적 개선

- `permuation`은 `permutation`, `calcuator`는 `calculator`가 올바른 철자입니다. 다만 위 DFS로 바꾸면 두 함수 자체가 필요 없어집니다.
- 네 개의 독립된 `if`는 현재 `i`가 한 값만 가지므로 결과에는 문제가 없지만, 기존 구조를 유지한다면 `elif`가 의도를 더 분명하게 보여 줍니다.
- 같은 폴더의 `input.txt`를 자동으로 여는 코드는 로컬에서는 편하지만, 다른 입력을 파이프로 넣어 테스트해도 저장된 파일을 우선 읽습니다. 제출용 코드에서는 제거하고 표준 입력만 사용하는 편이 테스트 실수를 줄입니다.

## 실행 검증

- 저장된 예시 입력의 **실제 출력**은 `[54, -24]`였습니다. 두 숫자의 값은 기대값과 같지만 출력 형식이 다릅니다.
- 최소 크기 음수 결과 입력 `2 / 1 2 / 0 1 0 0`의 **실제 출력**은 `[-1, -1]`이었습니다. 초기 최댓값과 음수 처리는 정상입니다.
- 음수 나눗셈을 포함한 입력 `3 / 1 4 3 / 0 1 0 1`의 **실제 출력**은 `[-1, -3]`이었고, 0 방향 버림 규칙과 일치했습니다.
- 최대 입력은 `3,628,800`개의 리스트 생성으로 실행 환경의 메모리를 과도하게 사용할 수 있어 직접 실행하지 않았습니다. 성능 판정은 위의 경우의 수와 저장 구조를 근거로 했습니다.

일부 실행 결과는 보조 근거일 뿐입니다. 연산 결과의 정확성은 모든 연산자 인덱스 순열을 포함한다는 점과 왼쪽부터의 계산 흐름으로 확인했고, 오답 판정은 출력 형식 불일치와 최악 입력의 복잡도를 근거로 했습니다.

## 이 문제에서 읽어야 할 신호

- **`N <= 11`** → 연산자 10자리를 모두 시도하는 완전 탐색이 가능한지 경우의 수를 계산해 볼 수 있습니다.
- **각 연산자의 개수가 주어짐** → 같은 연산자를 개별 원소로 펼치기보다, 남은 네 종류의 개수를 상태로 관리하면 중복을 피할 수 있습니다.
- **최댓값과 최솟값** → 한 가지 그리디 순서를 찾는 것이 아니라 가능한 모든 순서의 결과를 비교해야 합니다.
- **앞에서부터 계산** → 상태에는 지금까지의 누적 결과와 다음 숫자의 인덱스만 있으면 됩니다.

- 가장 먼저 보완할 부분은 **중복을 만든 뒤 제거하지 말고, 같은 선택을 처음부터 한 번만 탐색하는 것**입니다.
- 다음에는 순열을 리스트로 저장하기 전에 `최대 후보 수 x 후보 하나의 크기`를 계산해 보세요. 중복 원소가 있다면 인덱스 순열보다 **개수 기반 DFS**를 먼저 떠올리면 좋습니다.
- 제출 직전에는 샘플의 숫자값뿐 아니라 줄 수, 괄호, 쉼표까지 출력 형식과 같은지 확인하세요.
