# [이코테 / BOJ 18352] 특정 거리의 도시 찾기 풀이 첨삭

## 총평

- **판정**: 오답
- **핵심 이유**: 다익스트라로 계산한 최단 거리 배열은 정확하지만, `for ... else` 문 때문에 정답 도시가 있어도 항상 `-1`을 출력합니다. 또한 `solution()`이 거리 배열을 반환하고 `main`에서 그것을 다시 출력하여 출력 형식을 위반합니다.

## 문제 핵심

- `N`개의 도시와 `M`개의 **방향 도로**가 있고, 모든 도로의 거리는 1입니다.
- 출발 도시 `X`에서 최단 거리가 정확히 `K`인 모든 도시를 번호 오름차순으로 출력합니다.
- 해당 도시가 하나도 없을 때만 `-1`을 출력해야 합니다.
- 표준 제약은 `N <= 300,000`, `M <= 1,000,000`으로 크고 모든 간선의 가중치가 1이므로 BFS가 가장 적합합니다.

## 현재 접근법

- 인접 리스트를 만든 뒤, 다익스트라와 BFS 두 함수를 모두 구현했습니다.
- 현재는 65번 줄에서 `dijkstra(x)`만 호출합니다.
- 도시 번호를 0부터 차례로 확인하며 거리가 `K`인 번호를 출력하려는 구조입니다. 번호를 순서대로 확인하므로 별도 정렬은 필요 없습니다.

## 정확성 및 반례

### 반례 1: 정답 도시가 있는 경우

```text
4 4 1 1
1 2
1 3
2 3
2 4
```

- **기대 출력**

```text
2
3
```

- **실제 출력**

```text
2
3
-1
[100000000000000000000, 0, 1, 1, 2]
```

- **오류 흐름**: 파이썬의 `for ... else`에서 `else`는 `if`가 아니라 `for`에 속합니다. 루프가 `break`없이 끝나면 실행되며, 현재 루프에는 `break`가 없으므로 71번 줄의 `print(-1)`은 항상 실행됩니다. 그런 다음 72번 줄에서 반환한 배열을 77번 줄이 추가로 출력합니다.

### 반례 2: 정답 도시가 없는 경우

```text
2 0 1 1
```

- **기대 출력**: `-1`
- **코드 흐름상 예상 동작**: `-1`을 출력한 뒤, 도시 1의 거리가 0이고 도시 2는 무한대인 거리 배열까지 추가 출력합니다.

거리 계산 논리 자체는 정확합니다. 100개의 무작위 방향 그래프에서 다익스트라가 반환한 거리를 독립적인 BFS 결과와 비교했고 모두 일치했습니다. 하지만 온라인 저지는 출력 형식까지 정확해야 하므로 현재 전체 풀이는 오답입니다.

## 복잡도

`N`을 도시 수, `M`을 도로 수라고 하겠습니다.

- 현재 호출하는 다익스트라는 우선순위 큐 연산으로 **`O((N + M) log N)` 시간**이 걸립니다.
- 함께 작성한 BFS는 각 도시와 도로를 한 번씩 확인하므로 **`O(N + M)` 시간**이 걸립니다.
- 인접 리스트, 거리 배열, 큐나 힙의 **공간 복잡도는 `O(N + M)`**입니다.

다익스트라도 최단 거리는 정확히 구하지만, `N=300,000`, `M=1,000,000`에서 불필요한 로그 비용과 힙 연산을 추가합니다. 모든 간선의 가중치가 같으므로 작성해 둔 BFS를 사용하는 것이 제약에 더 적합합니다.

## 필수 수정

1. 65번 줄의 `distances = dijkstra(x)`를 `distances = bfs(x)`로 바꾸세요.
2. 거리가 `K`인 도시를 하나라도 출력했는지 `found` 변수로 기록하고, `found == False`일 때만 `-1`을 출하세요.
3. 거리 배열을 반환해 출력하는 72번 줄과 76~77번 줄의 구조를 정리해 `solution()`만 호출하세요.

출력부의 최소 수정 형태는 다음과 같습니다.

```python
distances = bfs(x)
found = False

for city in range(1, n + 1):
    if distances[city] == k:
        print(city)
        found = True

if not found:
    print(-1)
```

`main`에서는 `solution()`을 그대로 호출하고 반환값을 다시 `print()`하지 않아야 합니다.

## 선택적 개선

- `graphs = [[] for _ in range(n + 1)]`처럼 리스트로 인접 리스트를 만들면 대규모 입력에서 딝셔너리 조회 비용을 줄일 수 있습니다.
- BFS에서는 큐에 거리를 함께 저장하지 않고 도시 번호만 넣은 뒤 `distances[next_node] = distances[node] + 1`로 계산해도 됩니다.
- 목표거리 `K`보다 큰 도시의 인접 도시는 더 탐색하지 않도록 가지치기할 수 있습니다. 필수는 아니며 BFS 자체로도 제약을 만족합니다.

## 실행 검증

- 저장된 예시 입력을 직접 실행해 위에 적은 추가 출력 문제를 재현했습니다.
- 무작위 방향 그래프 100건에서 현재 다익스트라의 거리 배열은 BFS 기준 풀이와 모두 일치했습니다.
- 따라서 필수 수정의 1순위는 출력 조건이고, BFS 전환은 최대 입력을 위한 효율성 수정입니다.

## 이 문제에서 읽어야 할 신호

- **“모든 도로의 거리가 1”** → 우선순위 큐가 필요 없는 BFS 최단 거리
- **“최단 거리가 K인 모든 도시”** → 시작점으로부터의 거리 배열 필요
- **“오름차순 출력”** → 거리 계산 후 도시 번호 1부터 순회하면 별도 정렬 불필요
- **`N`, `M`이 매우 큼** → 가중치 조건을 보고 `O(N + M)` 풀이를 우선 검토

## 다음 문제를 위한 체크포인트

- 다익스트라와 BFS를 모두 구현하고 가중치 1인 점을 인식한 것은 좋습니다. 거리 갱신 논리도 정확합니다.
- 가장 우선해서 보완할 점은 **알고리즘 결과와 출력 조건을 따로 검증하는 습관**입니다.
- 파이썬의 `for ... else`는 “루프를 돌며 답을 못 찾음”을 표현할 때 유용하지만, 그 경우에는 답을 찾은 순간 `break`해야 합니다. 여러 답을 모두 출력해야 하는 이 문제에서는 `found` 플래그가 더 명확합니다.
