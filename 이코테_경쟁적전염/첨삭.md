# [이코테 / BOJ 18405] 경쟁적 전염 풀이 첨삭

## 총평

- **판정**: 정답
- **핵심 이유**: 모든 바이러스를 번호가 작은 순서로 큐에 넣은 뒤 다중 시작점 BFS를 수행합니다. BFS가 시간 순서를, 초기 큐 순서가 같은 시간의 바이러스 번호 우선순위를 보장합니다.

## 문제 핵심

- `N x N` 격자에 1부터 `K`번까지의 바이러스가 있고, 매초 상하좌우의 빈칸으로 퍼집니다.
- 같은 초에 여러 바이러스가 하나의 칸을 노리면 **번호가 작은 바이러스**가 먼저 번식합니다.
- `S`초가 지난 뒤 `(X, Y)`의 바이러스 번호를 구합니다.
- 표준 제약 `N <= 200`, `K <= 1,000`에서 격자의 각 칸을 한 번씩만 방문하는 BFS가 적합합니다.

## 현재 접근법

1. `viruses[id]`에 각 바이러스의 초기 위치를 모읍니다.
2. `viruses[1:]`를 순회하여 바이러스 번호가 작은 순서대로 모든 초기 위치를 `(row, col, time=0)`으로 큐에 넣습니다.
3. BFS로 빈칸을 발견하면 현재 바이러스 번호를 즉시 기록하고 `time + 1`로 큐에 넣습니다.
4. `time + 1 <= S`인 확산만 반영하고 목표 칸을 반환합니다.

## 정확성 및 반례

반례를 발견하지 못했습니다.

- 초기 큐의 `time=0` 상태는 바이러스 번호 오름차순으로 배치됩니다.
- BFS는 `time=t`인 모든 상태를 `time=t+1`보다 먼저 처리합니다.
- `time=t`인 상태들이 바이러스 번호 순서라면, 그들이 큐에 넣는 `time=t+1`의 상태들도 같은 순서를 유지합니다.
- 빈칸을 큐에 넣는 즉시 바이러스 번호로 바꾸므로, 같은 시간에 뒤에서 도착한 큰 번호가 그 칸을 덮어쓰지 못합니다.

이 순서가 모든 초에 유지되므로 문제의 경쟁 규칙과 정확히 일치합니다. `S=0`일 때도 새로운 확산을 하지 않아 초기 격자를 그대로 조회합니다.

## 복잡도

`N x N`을 격자 크기, `K`를 바이러스 종류 수라고 하겠습니다.

- 입력과 바이러스 위치 수집은 `N²`칸을 확인합니다.
- 초기 큐 구성은 `K`개의 목록과 초기 바이러스 수만큼 수행됩니다.
- 각 칸은 빈칸에서 바이러스로 바뀌 때 한 번만 큐에 들어갑니다.
- **시간 복잡도**: `O(N² + K)`
- **공간 복잡도**: 격자, 바이러스 목록, BFS 큐를 합해 `O(N² + K)`

## 필수 수정

없습니다.

## 선택적 개선

- 큐에서 `time == S`인 상태를 처리할 때 즉시 BFS를 종료하면 `S`초의 격자가 완성된 후 불필요한 큐 처리를 줄일 수 있습니다.
- `moves`는 변경할 필요가 없으므로 튜플 `((0, 1), (0, -1), (1, 0), (-1, 0))`로 두어도 좋습니다. 이는 가독성 선택이며 정답 여부에는 영향이 없습니다.
- 제출용 코드에서는 로컬 `input.txt`를 자동으로 여는 코드를 빼면 표준 입력으로 테스트하기 더 쉽습니다.

## 실행 검증

- 저장된 예시 입력의 **실제 출력은 `3`**으로 기대값과 일치했습니다.
- `S=0`을 포함한 1x1~5x5 무작위 격자 180건을 매초 번호순으로 직접 확산시키는 기준 풀이와 교차 검증했고 모두 일치했습니다.
- 무작위 테스트는 보조 근거이며, 전체 정확성은 BFS의 시간별·번호별 처리 순서로 판단했습니다.

## 이 문제에서 읽어야 할 신호

- **“매초 인접한 칸으로 퍼진다”** → 시간을 거리 레벨로 볼 수 있는 BFS
- **“번호가 낮은 바이러스부터 증식”** → BFS의 초기 큐를 바이러스 번호 순으로 구성
- **여러 시작점에서 동시 확산** → 시작점을 모두 먼저 큐에 넣는 다중 시작점 BFS
