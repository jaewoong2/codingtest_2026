# [프로그래머스 81302] 거리두기 확인하기 풀이 첨삭

## 총평

- **판정**: 정답
- **핵심 이유**: 각 응시자 `P`를 시작으로, 파티션 `X`를 통과하지 않는 BFS를 맨해튼 거리 2까지 수행합니다. 이 범위에서 다른 `P`를 발견하면 위반으로 판정하므로, 매우 가까운 응시자 사이의 모든 통로가 `X`로 막혔는지를 정확히 검사합니다.

## 문제 핵심

- 5개의 5x5 대기실이 주어집니다.
- `P`는 응시자, `O`는 빈 테이블, `X`는 파티션입니다.
- 맨해튼 거리가 2 이하인 두 `P`는, 사이의 모든 짧은 이동 경로가 `X`로 막힌 경우에만 허용됩니다.
- 각 대기실의 준수 여부를 1 또는 0으로 반환해야 합니다.

이 문제의 본질은 두 `P`의 직선거리만 재는 것이 아니라, **`X`를 통과하지 않고 2번 이하로 다른 `P`에 도달할 수 있는지** 확인하는 것입니다.

## 현재 접근법

1. 각 대기실의 모든 칸을 순회하며 `P`를 찾습니다.
2. 발견한 `P`에서 `get_candidates()` BFS를 시작합니다.
3. 상하좌우 중 `O`만 큐에 넣어 탐색하고, `X`는 큐에 넣지 않아 파티션 뒤를 탐색하지 않습니다.
4. 거리 2 이내에서 다른 `P`를 발견하면 해당 대기실을 즉시 0으로 판정합니다.
5. 모든 `P`에서 위반을 발견하지 못하면 1을 저장합니다.

BFS는 이 문제에 적합한 선택입니다. 모든 이동 비용이 1이므로, 큐에서 나오는 순서가 시작점으로부터의 거리 순서입니다.

## 정확성 및 반례

반례를 발견하지 못했습니다.

- 거리 1의 `P`는 시작점의 인접칸을 확인할 때 즉시 발견됩니다.
- 직선 거리 2에서 사이가 `O`이면 그 `O`를 통해 다른 `P`를 발견하고, `X`이면 탐색이 막힙니다.
- 대각선 거리 2에서는 두 개의 중간칸 중 하나라도 `O`면 그 경로로 `P`를 발견합니다. 두 칸이 모두 `X`인 경우에만 도달하지 못합니다.
- `visited`로 같은 빈 테이블을 중복 탐색하지 않습니다.
- `distance == 2`에서 `break`하는 것도 현재 코드에서는 정확합니다. BFS의 FIFO 순서 때문에 첫 거리 2 노드가 나올 때는 모든 거리 1 노드의 인접칸 검사가 이미 끝났습니다. 거리 2의 `P`는 그 거리 1 노드를 확장할 때 발견됩니다.

따라서 `X`로 막히지 않은 거리 2 이하의 `P`가 있을 때와 없을 때를 모두 정확히 구분합니다.

## 복잡도

`K`를 대기실 수, `R`, `C`를 행과 열의 크기라고 하겠습니다. 이 문제에서는 `K = 5`, `R = C = 5`입니다.

- 한 `P`의 BFS는 반경 2 안만 확인하므로 확인하는 칸과 간선 수가 상수입니다.
- 각 칸이 `P`인지 확인하고, 최악의 경우 모든 `P`에서 상수 범위 BFS를 하므로 **시간 복잡도는 `O(K x R x C)`**입니다.
- 큐와 `visited`에는 반경 2 안의 칸만 담기므로 이 문제의 고정된 탐색 거리에서 **추가 공간은 `O(1)`**입니다. 반환 배열까지 포함하면 `O(K)`입니다.

실제 입력은 5x5로 매우 작아 시간과 메모리 제한에 충분히 여유가 있습니다.

## 필수 수정

없습니다.

## 선택적 개선

- `get_candidates()`는 후보 목록이 아니라 **위반 발견 여부**를 반환합니다. `has_violation()` 같은 이름이 역할을 더 잘 드러냅니다.
- `is_blocked` 또한 `True`일 때 파티션으로 막혀 있다는 뜻처럼 읽힙니다. 실제 의미에 맞게 `has_violation`이나 `is_violated`로 바꾸면 조건문이 직관적입니다.
- `distance == 2` 시 `break`하는 코드는 정답이지만 BFS의 레벨 순서를 이해해야 안전성을 판단할 수 있습니다. `if distance >= 2: continue`로 표현하면 “거리 2 노드는 더 확장하지 않는다”는 의도가 더 분명해집니다.
- `import collections`를 함수가 호출될 때마다 실행해도 파이썬의 모듈 캐시 때문에 정답이나 복잡도에는 문제가 없습니다. 다만 일반적으로 `from collections import deque`를 파일 맨 위에 두면 의존성이 한눈에 보입니다.
- 주석의 “맨해튼 거리가 2인 애들”은 인접한 거리 1도 검사해야 하므로 “맨해튼 거리 2 이하”로 고치는 것이 정확합니다. 실제 코드는 거리 1도 올바르게 처리합니다.

## 실행 검증

- 공식 예제의 **실제 출력은 `[1, 0, 1, 1, 1]`**로 기대값과 일치했습니다.
- 두 `P`의 거리와 중간 파티션을 직접 확인하는 독립 기준 풀이와 무작위 5x5 대기실 **100,000건**을 교차 검증했고 모두 일치했습니다.
- 실행 테스트는 보조 근거이며, 모든 입력에 대한 정답 판정은 위 BFS의 도달 가능성 논리로 확정했습니다.

## 이 문제에서 읽어야 할 신호

- **“상하좌우로 이동한 거리”** → 각 칸을 정점으로 보는 격자 그래프 탐색
- **“맨해튼 거리 2 이하”** → 탐색 깊이를 2로 제한
- **“파티션으로 막힌 경우는 허용”** → `X`는 탐색하지 않는 장애물로 처리
- **격자가 5x5로 매우 작음** → 각 `P`에서 짧은 BFS를 반복해도 충분

## 다음 문제를 위한 체크포인트

- `X`를 큐에 넣지 않아 “파티션으로 막힌다”는 규칙을 BFS의 이동 규칙으로 자연스럽게 바꾼 점이 좋습니다.
- 위반을 하나라도 발견하면 두 중첩 반복문을 종료해 불필요한 탐색을 줄인 점도 적절합니다.
- 다음에는 BFS를 쓸 때 “큐에 넣은 시점에 방문 처리했는가?”와 “종료 조건이 현재 노드만 끝내는지, 전체 탐색을 끝내는지?”를 따로 확인해 보세요.
