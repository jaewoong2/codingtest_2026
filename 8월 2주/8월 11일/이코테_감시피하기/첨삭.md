## 총평

- **판정: 정답**
- **핵심 이유:** 장애물을 놓을 수 있는 모든 3개의 빈칸 조합을 확인하고, 각 배치마다 모든 선생님의 네 방향 시야를 빠짐없이 검사한다. `N <= 6`에서 시간과 메모리도 충분하다.
- 원본 `solution.py`는 수정하지 않았다.

## 문제 핵심

- 크기 `N x N`(`3 <= N <= 6`)인 복도에 학생 `S`, 선생님 `T`, 빈칸 `X`가 있다.
- 빈칸 중 정확히 3곳에 장애물 `O`를 설치한다.
- 선생님은 상하좌우 직선 방향을 보며, 장애물을 만나면 그 뒤는 보지 못한다.
- 장애물 3개를 설치해 모든 학생을 감시에서 피할 수 있으면 `YES`, 없으면 `NO`를 출력한다.

이 문제의 본질은 **장애물 3개의 모든 조합을 확인하는 완전탐색**과 **상하좌우 직선 시뮬레이션**이다. 가중치나 최단 거리를 구하는 문제가 아니므로 BFS는 필요하지 않다.

## 현재 접근법

1. 격자를 순회하며 빈칸과 선생님 위치를 저장한다.
2. `combination(empties, 3)`으로 장애물을 놓을 모든 조합을 만든다.
3. 한 조합의 세 칸을 `O`로 바꾼다.
4. 모든 선생님에 대해 네 방향을 `is_find()`로 탐색한다.
5. 학생을 하나도 발견하지 못한 배치가 있으면 `YES`를 반환한다.
6. 실패한 배치는 장애물을 다시 `X`로 복구하고 다음 조합을 확인한다.

장애물의 **순서는 의미가 없으므로 순열이 아닌 조합**을 사용한 점이 정확하다.

## 정확성 및 반례

### 왜 항상 정답인가?

- `combination()`이 서로 다른 빈칸 3개의 모든 조합을 정확히 한 번씩 생성한다. 따라서 가능한 장애물 배치를 놓치지 않는다.
- `is_find()`는 선생님의 바로 옆 칸부터 한 방향으로 한 칸씩 이동한다. 격자 밖이나 장애물에 도달하기 전에 학생을 만나면 감시된 것이므로 `True`를 반환한다.
- 모든 선생님의 모든 방향에서 학생이 보이지 않는 배치만 `YES`를 반환한다.
- 모든 배치가 실패해야만 `NO`를 반환한다.

따라서 유효한 배치가 있을 때와 없을 때를 모두 정확하게 판별한다. 논리 검토상 반례는 없다.

### 실행 검증

| 검증 내용                                       | 기대 출력 | 실제 출력 |
| ----------------------------------------------- | --------: | --------: |
| 현재 `input.txt`의 첫 번째 예제                 |     `YES` |     `YES` |
| 장애물 3개로도 피할 수 없는 예제                |      `NO` |      `NO` |
| `T X S`가 한 행에 있어 중간을 막을 수 있는 경우 |     `YES` |     `YES` |
| 선생님과 학생이 대각선에만 있는 경우            |     `YES` |     `YES` |

추가로 독립적인 기준 풀이와 `N=3..6` 무작위 격자 1,000개를 차분 비교했고, **1,000개 모두 결과가 일치**했다. 다만 이 테스트는 논리적 증명을 대체하지 않고 구현 실수가 없음을 보조하는 검증이다.

> `input.txt`에는 두 테스트가 연속해 있지만, 문제의 한 실행은 테스트 하나만 입력받는다. 현재 코드를 그대로 실행하면 첫 번째 테스트만 처리하는 것이 정상이다.

## 복잡도

- `E`: 빈칸의 수 (`E <= N^2`)
- `T`: 선생님의 수 (`T <= N^2`)
- 한 방향에서 확인하는 최대 칸 수: `N - 1`

### 시간 복잡도

- 장애물 배치 수: `C(E, 3)`
- 한 배치의 시야 검사: 최대 `T * 4 * (N - 1)`
- 전체: **`O(C(E, 3) * T * N)`**

`N=6`일 때 빈칸을 36개로 놓고 계산해도 `C(36, 3) = 7,140`개이다. 각 배치에서 직선 시야를 확인해도 제한 안에서 충분하다.

### 공간 복잡도

- 격자, 빈칸, 선생님 위치: `O(N^2)`
- 현재 구현은 모든 조합을 `candidates`에 미리 저장: **`O(C(E, 3))`**
- 조합 생성 재귀 깊이는 3으로 안전하다.

최대 7,140개의 3원소 조합만 저장하므로 현재 구현도 메모리 제한을 충분히 만족한다.

## 필수 수정

없다. 정확성, 시간 제한, 메모리 제한에 영향을 주는 문제를 발견하지 못했다.

## 선택적 개선

1. **표준 라이브러리 조합 사용**

   현재 `combination()`은 올바르게 동작한다. 다만 이미 가져온 `math.comb`는 조합의 **개수**만 계산하며, 조합 자체를 만들지 않는다. `itertools.combinations(empties, 3)`을 사용하면 커스텀 함수와 사용하지 않는 `math.comb` import를 없앨 수 있고, 조합을 한 개씩 생성해 추가 메모리도 줄일 수 있다.

2. **직선 이동 표현 단순화**

   `is_find()`의 `i`, `j`는 항상 1이므로 의미가 없다. `dr`, `dc`를 받아 `n_row += dr`, `n_col += dc`로 이동하면 “한 방향으로 한 칸씩 간다”는 의도가 더 잘 보인다.

3. **실패를 발견하면 즉시 시야 검사 종료**

   한 명의 학생이라도 발견되면 현재 장애물 배치는 실패다. 그 즉시 반복문을 종료하면 불필요한 탐색을 줄일 수 있다. 현재도 `N <= 6`이라 성능 문제는 없다.

4. **재귀 함수의 기본 인자 정리**

   `def c(start, chosen=[])`의 빈 리스트 기본값은 현재 코드에서 직접 변경되지 않고, `c(0, [])`로 명시적으로 전달되므로 오류를 만들지는 않는다. 그래도 파이썬의 변경 가능한 기본값은 재사용되는 실수를 만들기 쉬우므로 `def c(start, chosen):`처럼 기본값을 없애는 편이 좋다.

5. **로컬 입력 리다이렉션의 범위 인지**

   현재는 같은 폴더에 `input.txt`가 있으면 항상 그 파일을 읽는다. 그러므로 로컬에서 터미널로 다른 입력을 파이핑해도 `input.txt`가 우선된다. 온라인 저지에는 해당 파일이 없어 보통 문제가 없지만, 제출용 코드에서는 제거하면 입력 흐름이 더 명확해진다.

## 이 문제에서 읽어야 할 신호

- **`N <= 6`**: 격자가 최대 36칸으로 매우 작다. 최적화 알고리즘부터 찾기보다 전체 경우의 수를 먼저 계산해야 한다.
- **“장애물 3개”**: 빈칸이 최대 36개여도 `C(36, 3) = 7,140`이므로 조합 완전탐색이 가능하다.
- **“상하좌우 방향으로 감시”, “장애물 뒤는 보지 못함”**: 각 선생님에서 네 방향으로 격자 밖이나 장애물을 만날 때까지 직선 탐색하면 된다.
- **장애물의 배치 순서는 결과에 영향을 주지 않음**: 순열이 아닌 조합을 사용해야 중복 탐색을 피할 수 있다.

## 다음 문제를 위한 체크포인트

- **잘한 점:** 입력 크기에 맞게 장애물 배치를 조합으로 완전탐색했고, 각 실패 후 격자를 `X`로 복구해 다음 경우에 영향을 주지 않게 했다.
- **잘한 점:** 시야를 BFS나 DFS로 과도하게 풀지 않고, 방향 벡터를 활용한 직선 탐색으로 표현했다.
- **우선 보완점:** 코드를 작성하기 전에 `C(빈칸 수, 3)`을 실제 최댓값으로 계산해, 완전탐색이 통과할 수 있는 이유를 스스로 먼저 확인해 보자.
- **기억할 문장:** “격자가 작고, 정확히 `K`개를 선택하며, 순서가 중요하지 않다면 `C(후보 수, K)`부터 계산한다.”
