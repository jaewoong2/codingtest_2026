## 총평

- 판정: **오답**
- 핵심 이유: 정렬 기준 자체는 정확하지만, 제출 출력이 파이썬 리스트 형태이고 직접 구현한 퀵 정렬은 최악의 경우 `O(N²)`과 깊은 재귀가 발생합니다. `N`이 최대 100,000이므로 정답 코드로 보기 어렵습니다.

## 문제 핵심

학생을 다음 우선순위로 정렬한 뒤 이름을 한 줄에 하나씩 출력하는 문제입니다.

1. 국어 점수 내림차순
2. 국어 점수가 같으면 영어 점수 오름차순
3. 국어와 영어 점수가 같으면 수학 점수 내림차순
4. 모든 점수가 같으면 이름 사전순

학생 수가 최대 100,000명이므로 최악의 경우에도 `O(N log N)`이 보장되는 정렬을 사용해야 합니다.

## 현재 접근법

`compare()`에 네 가지 정렬 기준을 순서대로 구현하고, 첫 원소를 피벗으로 삼는 재귀 퀵 정렬을 작성했습니다. 정렬이 끝난 뒤에는 이름만 리스트로 만들어 반환하고 메인에서 그 리스트를 출력합니다.

정렬 기준을 조건 순서 그대로 옮긴 점은 정확합니다. 특히 영어만 오름차순이고 나머지 두 점수는 내림차순이라는 차이를 잘 처리했습니다.

## 정확성 및 반례

### 1. 출력 형식 오류

문제는 이름을 한 줄에 하나씩 출력해야 하지만 현재 코드는 리스트 표현을 한 줄에 출력합니다.

반례 입력:

```text
1
A 100 100 100
```

기대 출력:

```text
A
```

코드 흐름상 예상 출력:

```text
['A']
```

저장소의 예제 입력으로 직접 실행했을 때도 `['Donghyuk', ...]` 형태의 리스트 한 줄이 출력됐습니다.

### 2. 퀵 정렬의 최악 입력

항상 첫 원소를 피벗으로 고르므로 입력이 이미 정답 순서이거나 그 역순에 가까우면 한쪽 부분 배열의 크기가 계속 `N-1`이 됩니다. 이 경우 재귀 깊이가 `O(N)`까지 증가해 파이썬의 재귀 한도를 넘을 수 있고, 분할 작업도 총 `O(N²)`이 됩니다.

학생 이름은 서로 다르므로 `compare(x, pivot)`과 `compare(pivot, x)` 중 하나가 참이 되어 원소가 사라지는 문제는 없습니다.

## 복잡도

- `N`: 학생 수
- 현재 코드의 평균 시간: `O(N log N)`
- 현재 코드의 최악 시간: `O(N²)`
- 추가 공간: 평균적으로 `O(N)`, 치우친 분할에서는 재귀 중 크기가 감소하는 리스트들이 겹쳐 남아 최악 `O(N²)`까지 커질 수 있습니다.
- 파이썬 내장 정렬 사용 시 시간은 최악 `O(N log N)`, 정렬 대상 저장 공간은 `O(N)`입니다.

`N=100,000`에서 현재 방식의 최악 시간과 재귀 깊이는 제한을 만족하지 못합니다.

## 필수 수정

내장 정렬에 복합 키를 전달하고, 결과를 줄바꿈으로 출력해야 합니다.

```python
students.sort(key=lambda x: (-x[1], x[2], -x[3], x[0]))
print("\n".join(student[0] for student in students))
```

음수 키는 큰 점수를 먼저 오게 하고, 양수 키는 작은 점수를 먼저 오게 합니다. 튜플은 앞 원소부터 비교되므로 문제의 우선순위가 그대로 표현됩니다.

## 선택적 개선

- 사용하지 않는 `from re import I`를 제거할 수 있습니다.
- `studentes`는 `students`로 고치면 오타로 인한 혼동을 줄일 수 있습니다.
- 로컬 `input.txt` 자동 연결은 제출 환경에 파일이 없으면 동작하지만, 임의 표준 입력으로 테스트할 때 같은 폴더의 파일을 우선 읽는다는 점은 기억해야 합니다.

## 이 문제에서 읽어야 할 신호

“A 기준 내림차순, 같으면 B 기준 오름차순”처럼 정렬 우선순위가 연속해서 주어지면 비교 함수를 직접 만들기 전에 **튜플 키 정렬**을 먼저 떠올리세요. 입력 크기가 100,000이면 직접 구현한 단순 피벗 퀵 정렬의 최악 상황도 반드시 확인해야 합니다.
