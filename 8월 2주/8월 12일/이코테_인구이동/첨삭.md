# 인구 이동 풀이 첨삭

## 총평

- **판정: 오답**
- **핵심 이유:** 하루마다 격자를 탐색하여 연합을 만들고, 연합별 평균 인구를 한꺼번에 반영하는 알고리즘은 맞습니다. 하지만 재귀 DFS의 깊이가 최대 `N² = 2,500`까지 커질 수 있는데, 파이썬의 기본 재귀 한도는 보통 약 1,000이므로 유효한 최대 입력에서 `RecursionError`가 발생합니다.
- 일반적인 입력에서는 정답처럼 동작하므로, 알고리즘을 바꿀 필요는 없습니다. **재귀 DFS를 반복형 BFS/DFS로 바꾸는 것**이 가장 안전한 필수 수정입니다.

## 문제 핵심

- `N × N` 격자에서 상하좌우로 인접한 두 나라의 인구 차이가 `L` 이상 `R` 이하이면 국경을 엽니다.
- 같은 날 열린 국경으로 연결된 나라 전체가 하나의 **연합**, 즉 하나의 연결 요소가 됩니다.
- 연합의 인구를 `연합 인구 합 // 연합 칸 수`로 동시에 변경합니다.
- 더는 크기 2 이상의 연합이 만들어지지 않을 때까지 반복하고, 인구 이동이 일어난 날짜 수를 출력합니다.
- 표준 문제의 주요 제약은 `1 ≤ N ≤ 50`이므로 한 연합에 최대 2,500개 나라가 들어갈 수 있습니다.

놓치기 쉬운 핵심은 두 가지입니다.

1. 한 연합을 찾는 도중에는 인구를 변경하면 안 됩니다. 그날의 모든 연합을 현재 인구를 기준으로 먼저 결정해야 합니다.
2. 하루의 종료 여부는 “인구 값이 실제로 달라졌는가”가 아니라, **크기 2 이상의 연합이 하나라도 생겼는가**로 판단합니다.

## 현재 접근법

현재 코드는 다음 순서로 동작합니다.

1. 아직 어느 연합에도 포함되지 않은 칸에서 DFS를 시작합니다.
2. 인구 차이가 범위 안에 있는 인접 칸을 `visited`에 추가하여 하나의 연합을 찾습니다.
3. 찾은 연합들을 `nodes`에 모두 저장합니다.
4. 모든 연합 탐색이 끝난 후, 크기 2 이상인 연합의 평균 인구를 계산해 `maps`에 반영합니다.
5. 크기 2 이상의 연합이 하나도 없으면 종료하고, 아니면 `count`를 1 증가시켜 다음 날을 시뮬레이션합니다.

연합을 **연결 요소 탐색 문제**로 바꿔 생각한 것과, 탐색이 모두 끝난 뒤 인구를 갱신한 것은 정확합니다.

## 정확성 및 반례

### 맞게 처리한 부분

- 시작 칸을 DFS 전에 방문 처리하여 같은 연합 안에서 중복 탐색하지 않습니다.
- `all_visited`를 이용해 하루 동안 모든 칸을 정확히 하나의 연합에 포함시킵니다.
- 연합 탐색을 전부 끝낸 뒤 인구를 갱신하므로, 갱신된 값이 같은 날 다른 연합 판정에 영향을 주지 않습니다.
- `len(values) > 1`인 연합이 하나라도 있으면 하루를 증가시키는 종료 조건도 문제 정의와 맞습니다.
- 28~34행의 두 조건은 장황하지만, 두 인구의 차이에 절댓값을 적용한 것과 논리적으로 같습니다.

### 필수 오류: 재귀 깊이 초과

현재 `dfs()`는 연합에 속한 나라를 재귀 호출로 방문합니다. 최악의 경우 한 연합의 크기는 2,500이고 재귀 호출도 그에 비례해 깊어질 수 있습니다.

다음과 같은 유효 입력 형태로 직접 실행했을 때 오류를 확인했습니다.

```text
50 1 1
0 1 0 1 ... (50개)
1 0 1 0 ... (50개)
... 위 두 행을 번갈아 총 50행
```

- 모든 상하좌우 이웃의 인구 차이는 정확히 1이므로 2,500칸 전체가 하나의 연합입니다.
- 기대 결과는 첫날 전체 인구가 `0`이 된 뒤 더는 국경이 열리지 않으므로 `1`입니다.
- **실제 실행 결과:** 값을 출력하지 못하고 `RecursionError: maximum recursion depth exceeded`가 발생했습니다.
- 오류 흐름: `solution.py` 30행과 34행의 재귀 호출이 기본 재귀 한도를 넘습니다.

알고리즘의 논리는 맞지만 입력 제약 안에서 런타임 오류가 나는 경우가 있으므로 현재 상태는 정답이 아닙니다.

## 복잡도

- `N`: 격자의 한 변 길이
- `D`: 인구 이동이 일어나는 날짜 수

하루마다 모든 칸을 한 번씩 연합에 포함시키고, 각 칸에서 상하좌우 네 방향만 확인합니다. 연합별 합산과 인구 갱신을 합쳐도 하루에 모든 칸을 한 번 더 보는 정도입니다.

- 시간 복잡도: **`O(D × N²)`**
- 공간 복잡도: **`O(N²)`**

`all_visited`, 모든 `visited` 집합의 원소 합, `nodes`가 각각 격자 크기에 비례합니다. 재귀 DFS의 호출 스택도 이론상 `O(N²)`인데, 파이썬에서는 이 호출 깊이가 기본 제한을 넘어가는 것이 현재 오류의 직접 원인입니다.

## 필수 수정

### 권장: 재귀 DFS를 반복형 BFS로 변경

기존 구조를 유지하면서 `dfs()`만 다음과 같은 형태로 바꾸면 됩니다. `deque`를 사용하면 호출 깊이 제한 없이 같은 연결 요소를 찾을 수 있습니다.

```python
from collections import deque

def bfs(start_row, start_col):
    union = {(start_row, start_col)}
    queue = deque([(start_row, start_col)])

    while queue:
        row, col = queue.popleft()

        for dr, dc in moves:
            nr, nc = row + dr, col + dc

            if not (0 <= nr < n and 0 <= nc < n):
                continue
            if (nr, nc) in union:
                continue
            if not (l <= abs(maps[row][col] - maps[nr][nc]) <= r):
                continue

            union.add((nr, nc))
            queue.append((nr, nc))

    return union
```

현재 반복문에서는 아래처럼 호출하면 됩니다.

```python
visited = bfs(i, j)
```

`sys.setrecursionlimit()`을 2,500보다 크게 설정하는 것도 최소 변경으로는 가능하지만, 격자 탐색에서는 반복형 BFS/DFS가 실행 환경의 재귀 제한에 의존하지 않아 더 안전합니다.

## 선택적 개선

### 1. 인구 차이 조건 단순화

현재 두 조건은 다음 한 줄로 합칠 수 있습니다.

```python
if l <= abs(maps[row][col] - maps[nr][nc]) <= r:
```

문제 문장의 “인구 차이”를 코드에 그대로 표현하므로 의도가 더 빠르게 보입니다.

### 2. 전체 방문 집합 갱신 단순화

```python
all_visited.update(visited)
```

48~49행의 반복문과 같은 동작입니다.

### 3. 중복 초기화 제거

`count = 0`이 19행과 36행에 두 번 있습니다. 하나만 남겨도 됩니다. 정답에는 영향을 주지 않습니다.

### 4. 제출 코드와 로컬 입력 도우미 분리

`input.txt` 자동 연결 코드는 로컬 연습에는 편리하지만 문제 풀이의 핵심과 무관합니다. 제출 파일에는 표준 입력 코드만 두면 더 간결하고, 같은 폴더에 우연히 `input.txt`가 있는 다른 실행 환경에서도 입력이 바뀌지 않습니다.

## 이 문제에서 읽어야 할 신호

- **“상하좌우로 인접” + “연결된 나라가 하나의 연합”** → 격자를 그래프로 보고 BFS/DFS로 연결 요소를 찾습니다.
- **“인구 이동은 하루 동안 동시에 발생”** → 탐색 도중 값을 바꾸지 말고, 연합을 완성한 뒤 갱신합니다.
- **“더 이상 이동이 없을 때까지”** → 한 번의 탐색으로 끝나는 문제가 아니라, 상태가 안정될 때까지 전체 탐색을 반복하는 시뮬레이션입니다.
- **`N ≤ 50`** → 하루에 `O(N²)` 전체 탐색을 반복하는 방식은 가능하지만, 재귀 깊이는 최대 `N²`까지 갈 수 있는지 별도로 확인해야 합니다.
