# 블록 이동하기 풀이 첨삭

## 총평

- **판정: 정답**
- **핵심 이유:** 로봇이 차지하는 두 좌표를 하나의 상태로 보고, 이동과 회전을 모두 간선 비용 1인 상태 전이로 만들어 BFS를 수행했습니다. 가능한 상태를 빠짐없이 생성하며 방문 처리도 되어 있으므로 목적지까지의 최소 시간을 구합니다.
- 회전 코드가 길고 경우가 많아서 읽는 사람뿐 아니라 작성자 본인도 정확성을 검증하기 어려운 구조입니다. 이 문제에서 1시간 이상 걸린 핵심 원인은 BFS 자체보다 **상태 정규화와 회전 전이 열거**였을 가능성이 큽니다.

## 문제 핵심

- `2 × 1` 로봇이 `N × N` 격자에서 두 칸을 차지합니다.
- 상하좌우 평행 이동과, 두 칸 중 하나를 축으로 하는 90도 회전이 가능합니다.
- 이동과 회전 비용은 모두 1초입니다.
- 로봇의 두 칸 중 하나가 `(N, N)`에 도착하는 최소 시간을 구합니다.
- `5 ≤ N ≤ 100`이고 목적지에 도달할 수 있는 입력만 주어집니다.

이 문제의 본질은 일반적인 “한 칸의 위치”가 아니라 **서로 인접한 두 칸의 조합이 하나의 정점인 최단 거리 문제**라는 점입니다.

## 현재 접근법

현재 코드는 다음 상태를 큐에 저장합니다.

```text
(r1, c1, r2, c2, state)
```

- `(r1, c1)`, `(r2, c2)`: 로봇이 차지하는 두 칸
- `state == 0`: 수평
- `state == 1`: 수직

BFS에서 다음 상태를 만듭니다.

1. 두 칸을 동시에 상하좌우로 한 칸 이동합니다.
2. `rotate()`에서 현재 방향에 따라 가능한 네 가지 회전을 만듭니다.
3. 새 좌표 조합의 거리를 현재 거리에 1을 더해 저장합니다.
4. 탐색이 끝난 뒤 목적지를 포함할 수 있는 수평·수직 상태의 거리 중 최솟값을 반환합니다.

알고리즘 선택은 정확합니다. 모든 행동의 비용이 같기 때문에 BFS가 가장 먼저 찾은 거리가 최소 거리입니다.

## 정확성 검토

### 1. 상태 표현이 충분합니다

로봇의 다음 행동은 현재 차지한 두 칸만 알면 결정할 수 있습니다. 따라서 `(r1, c1, r2, c2)`에는 앞으로의 탐색에 필요한 정보가 모두 들어 있습니다.

`state`도 함께 저장했지만 두 좌표가 같은 행이면 수평, 같은 열이면 수직이므로 사실 좌표에서 계산할 수 있습니다. 중복 정보이긴 해도 현재 코드에서는 항상 좌표와 일치하게 갱신되어 정답에 영향을 주지 않습니다.

### 2. 좌표 순서가 항상 정규화됩니다

현재 코드는 명시적으로 정렬하지는 않지만 다음 불변식을 유지합니다.

- 수평 상태: 첫 좌표가 왼쪽, 두 번째 좌표가 오른쪽
- 수직 상태: 첫 좌표가 위쪽, 두 번째 좌표가 아래쪽

시작 상태 `(0, 0, 0, 1)`이 이 순서를 만족하고, 평행 이동은 순서를 바꾸지 않습니다. `rotate()`가 생성하는 네 상태도 모두 같은 순서로 넣습니다.

이 불변식 때문에 다음이 모두 성립합니다.

- 같은 로봇 배치를 좌표 순서만 바꿔 두 번 방문하지 않습니다.
- `rotate()`가 항상 `(r1, c1)`을 왼쪽 또는 위쪽 좌표로 가정해도 됩니다.
- 165~169행에서 목적지를 포함하는 두 가지 정규 상태만 검사해도 충분합니다.

이 부분은 현재 코드의 정확성을 지탱하는 중요한 조건입니다. 이후 코드를 고칠 때 회전 결과의 좌표 순서가 뒤집히면 같은 배치를 다른 상태로 취급할 수 있으므로 주의해야 합니다.

### 3. 평행 이동 조건이 정확합니다

두 칸 모두 격자 안이고 벽이 아닐 때만 다음 상태를 큐에 넣습니다. 로봇 전체가 한 칸 이동한다는 조건을 그대로 확인하고 있습니다.

### 4. 회전 조건이 정확합니다

수평 상태에서는 위쪽 또는 아래쪽의 두 칸이 모두 비어 있을 때 각 끝점을 축으로 하는 두 회전을 추가합니다. 수직 상태에서는 왼쪽 또는 오른쪽의 두 칸을 같은 방식으로 검사합니다.

즉 한 방향마다 회전 공간인 `2 × 2` 영역의 나머지 두 칸을 모두 검사하므로, 로봇이 벽을 통과하는 잘못된 회전은 생성하지 않습니다. `is_out(...) or maps[...] == 1`은 파이썬의 단락 평가 덕분에 범위 밖 좌표로 `maps`에 접근하지도 않습니다.

### 5. BFS의 최소 거리 성질을 만족합니다

이동과 회전은 모두 비용이 1입니다. 큐에는 시작 상태에서 거리 1만큼 먼 상태가 순서대로 들어가므로, 어떤 상태를 처음 발견했을 때 기록한 거리가 그 상태까지의 최소 거리입니다.

따라서 148~150행과 159~161행의 “더 짧은 경로이면 갱신” 분기는 실제로 필요하지 않지만, 결과를 틀리게 만들지는 않습니다.

### 6. 도착 상태 검사가 정확합니다

좌표 순서 불변식에 따라 `(N-1, N-1)`을 포함하는 정규 상태는 다음 두 개뿐입니다.

- 수평: `(N-1, N-2), (N-1, N-1)`
- 수직: `(N-2, N-1), (N-1, N-1)`

165~169행에서 둘 다 확인하므로 목적지 판정 누락이 없습니다.

## 실행 검증

원본 파일은 수정하지 않고 직접 호출하여 검증했습니다. 별도로 작성한 기준 BFS는 두 좌표를 정렬한 상태로 저장하고 이동·회전을 독립적으로 생성했습니다.

| 검증 | 결과 |
|---|---:|
| 프로그래머스 대표 예제 | 기대 `7`, 실제 `7` |
| `N=2` 가능한 벽 배치 전수조사 | 불일치 0건 |
| `N=3` 가능한 벽 배치 64개 전수조사 | 도달 가능 12개 중 불일치 0건 |
| `N=4` 가능한 벽 배치 8,192개 전수조사 | 도달 가능 638개 중 불일치 0건 |
| `N=5, 8, 15` 무작위 보드 각 500개 | 도달 가능한 보드에서 불일치 0건 |

이 테스트만으로 모든 입력을 증명하는 것은 아니지만, 위의 상태 전이와 BFS 논리 검토를 뒷받침합니다.

## 복잡도

- `N`: 보드 한 변의 길이

가능한 로봇 배치는 다음과 같습니다.

- 수평 상태: 각 행마다 `N-1`개이므로 `N(N-1)`개
- 수직 상태: 각 열마다 `N-1`개이므로 `N(N-1)`개
- 전체 상태 수: 최대 `2N(N-1)`, 즉 `O(N²)`

각 상태에서 평행 이동 4개와 회전 최대 4개만 확인하므로 상태당 작업량은 상수입니다.

- **시간 복잡도: `O(N²)`**
- **공간 복잡도: `O(N²)`**

`N=100`일 때 이론상 로봇 상태는 최대 19,800개이므로 현재 방식은 제약 안에서 충분히 처리 가능합니다.

## 필수 수정

정답 여부에 영향을 주는 필수 수정은 없습니다.

## 선택적 개선

### 1. BFS 거리 완화 제거

간선 비용이 모두 1인 BFS에서는 처음 방문한 거리가 최소 거리입니다. 다음 분기는 제거할 수 있습니다.

```python
elif visited[next_position] > visited[current_position] + 1:
    ...
```

방문하지 않은 상태만 큐에 추가하면 충분합니다. 이 원리를 알고 있으면 다익스트라식 갱신과 BFS 방문 처리를 구분하기 쉬워집니다.

### 2. 목적지를 꺼내는 즉시 종료

현재 코드는 목적지에 도달한 후에도 모든 도달 가능한 상태를 끝까지 탐색합니다. BFS 큐에서 상태를 꺼냈을 때 두 좌표 중 하나가 목적지라면 그 거리가 최소이므로 즉시 반환할 수 있습니다.

```python
if (r1, c1) == (n - 1, n - 1) or (r2, c2) == (n - 1, n - 1):
    return visited[(r1, c1, r2, c2)]
```

최악의 시간 복잡도는 같지만 불필요한 탐색을 줄이고 도착 조건도 문제 문장과 직접 대응합니다.

### 3. `state`는 좌표에서 계산 가능

```python
is_horizontal = r1 == r2
```

방향을 별도로 큐에 저장하지 않으면 좌표와 `state`가 불일치할 가능성 자체가 사라집니다. 현재 코드는 불일치하지 않으므로 필수 수정은 아닙니다.

### 4. 회전 로직의 중복 축소

현재 `rotate()`는 가능한 여덟 회전 조건을 직접 작성해 100줄가량 됩니다. 정답이지만 다음 위험이 있습니다.

- 한 좌표의 `+1`, `-1`을 잘못 적어도 눈으로 찾기 어렵습니다.
- 네 경우가 대칭이라는 문제 구조가 코드에서 잘 드러나지 않습니다.
- 좌표 순서 불변식을 유지하는지 매번 수동 검증해야 합니다.

예를 들어 수평일 때는 위·아래 두 방향만 반복하면서, 공간이 비면 두 축의 회전을 함께 추가할 수 있습니다.

```python
if r1 == r2:  # 수평
    for dr in (-1, 1):
        nr = r1 + dr
        if 0 <= nr < n and maps[nr][c1] == 0 and maps[nr][c2] == 0:
            next_positions.append(((r1, c1), (nr, c1)))
            next_positions.append(((r2, c2), (nr, c2)))
```

수직 상태도 `dc in (-1, 1)`로 대칭적으로 작성할 수 있습니다. 상태를 넣기 전에 두 좌표를 정렬한 튜플로 만들면 좌표 순서에 대한 암묵적 의존도 제거할 수 있습니다.

### 5. 이름으로 역할 드러내기

- `maps` → `board`
- `state` → `direction` 또는 좌표에서 방향 계산
- `answer` in `rotate()` → `next_positions`

현재 코드도 읽을 수 있지만, 특히 `answer`는 최종 정답이 아니라 다음 상태 목록이므로 역할이 드러나는 이름이 더 적절합니다.

## 이 문제에서 읽어야 할 신호

- **“최소 시간” + 모든 행동이 정확히 1초** → 가중치가 같은 최단 거리이므로 BFS를 우선 검토합니다.
- **로봇이 두 칸을 동시에 차지함** → 한 좌표가 아니라 두 좌표의 조합을 방문 상태로 저장해야 합니다.
- **평행 이동뿐 아니라 회전 가능** → 격자의 상하좌우 네 이동만으로는 부족하며, 회전을 별도의 상태 전이로 생성해야 합니다.
- **두 칸 중 어느 칸이든 회전축 가능** → 한 방향으로 회전할 때 결과가 두 개씩 나온다는 신호입니다.
- **회전 방향에 벽이 없어야 함** → 회전 후 도착 칸 하나만 보지 말고, 회전이 지나가는 `2 × 2` 공간을 확인해야 합니다.

## 다음 문제를 위한 체크포인트

- 잘한 점: 로봇 전체를 하나의 BFS 상태로 만든 판단이 정확했고, 네 방향 이동과 각 끝점 기준 회전을 모두 구현했습니다.
- 특히 좋은 점: 좌표 순서를 일관되게 유지하여 같은 배치를 중복 상태로 만들지 않았습니다.
- 가장 우선할 보완점: 대칭적인 경우를 하나씩 직접 쓰기 전에, `(-1, 1)` 반복으로 묶을 수 있는지 먼저 찾아보세요. 이번 코드의 정확성보다 **검증 비용**을 크게 줄여 줍니다.
- 다음 문제에서 기억할 질문: “움직이는 물체가 여러 칸을 차지한다면, 방문 배열의 한 상태에는 어떤 정보가 모두 들어가야 하는가?”

## 한 줄 회고

이 문제를 1시간 넘게 풀었다고 해서 BFS가 약한 것은 아닙니다. 이 문제의 실제 난도는 BFS 선택 이후에 있습니다. **복합 상태를 정의하고, 회전을 빠짐없이 생성하며, 같은 배치를 하나의 상태로 정규화하는 것**이 핵심 고비인데 현재 코드는 그 세 가지를 모두 해결했습니다.
