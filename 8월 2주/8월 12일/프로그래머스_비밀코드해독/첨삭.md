# [프로그래머스 388352] 비밀 코드 해독 풀이 첨삭

## 총평

- **판정**: 정답
- **핵심 이유**: 가능한 비밀 코드는 `1`부터 `n`까지의 수 중 서로 다른 5개를 고른 조합뿐입니다. 현재 코드는 이 조합을 빠짐없이 한 번씩 생성하고, 모든 질의에서 교집합의 크기가 `ans`와 같은 후보만 세므로 정확합니다. 최대 후보 수도 `30C5 = 142,506`개라 완전탐색이 가능합니다.

## 문제 핵심

- `1`부터 `n`까지의 서로 다른 정수 5개가 비밀 코드이며, 오름차순으로 표현됩니다.
- 각 질의 `q[i]`에는 서로 다른 정수 5개가 있고, `ans[i]`는 그중 비밀 코드에도 포함된 수의 개수입니다.
- 모든 질의 결과와 일치하는 5개 조합의 개수를 구해야 합니다.
- 제약은 `10 <= n <= 30`, `1 <= m <= 10`입니다.

비밀 코드의 순서는 이미 오름차순으로 정해져 있으므로 순열이 아니라 **조합**만 확인하면 된다는 점이 핵심입니다.

## 현재 접근법

1. `combination(numbers, 5)`로 `1..n`에서 5개를 고르는 모든 조합을 만듭니다.
2. 각 후보 `candidate`에 대해 모든 질의 `query`를 확인합니다.
3. 질의의 5개 수 중 후보에 포함된 수를 세어 `answer`에 저장합니다.
4. 계산한 전체 결과가 `ans`와 같으면 `result`를 1 증가시킵니다.

조합 생성에서 다음 재귀 호출을 `c(i + 1, ...)`로 제한했기 때문에 같은 수를 다시 고르지 않고, 오름차순 조합을 중복 없이 생성한 점이 좋습니다.

## 정확성 및 반례

반례를 발견하지 못했습니다.

- `combination()`은 각 단계에서 이전에 고른 인덱스보다 뒤의 원소만 선택합니다. 따라서 길이 5인 모든 조합을 정확히 한 번씩 생성합니다.
- 어떤 후보가 실제 가능한 비밀 코드이려면 모든 `i`에 대해 `|candidate ∩ q[i]| == ans[i]`여야 합니다.
- 내부 반복문은 각 `q[i]`의 원소 5개를 모두 검사하므로 이 교집합 크기를 정확히 계산합니다.
- 계산 결과 목록 전체가 `ans`와 같은 후보만 세기 때문에, 조건을 하나라도 만족하지 않는 후보는 제외되고 모든 조건을 만족하는 후보는 포함됩니다.

즉, 가능한 후보 전체를 빠짐없이 검사하고 필요충분조건으로 걸러 내므로 결과가 정확합니다.

## 복잡도

`C = nC5`, `M = len(q)`라고 하겠습니다. 최댓값은 `C = 30C5 = 142,506`, `M = 10`입니다.

- 조합 생성은 `C`개의 길이 5 리스트를 만드므로 `O(C)`개의 후보를 생성합니다. 숫자 5개까지 포함해 쓰면 `O(5C)`입니다.
- 후보 하나마다 `M`개의 질의를 확인합니다.
- 질의마다 수 5개를 검사하고, 리스트인 `candidate`에서 `in` 연산은 최악에 5개를 비교합니다. 따라서 최대 약 `C × M × 5 × 5`번의 작은 정수 비교가 이루어집니다.
- 5가 고정된 상수이므로 전체 시간 복잡도는 **`O(C × M)`**, 더 일반적으로 적으면 **`O(nC5 × M × 25)`**입니다.
- `candidates`에 모든 조합을 저장하므로 추가 공간 복잡도는 **`O(C × 5)`**, 즉 `O(C)`입니다. 재귀 깊이는 5로 매우 작습니다.

최대 입력에서도 후보가 142,506개이고 질의가 10개뿐이므로 시간과 메모리 모두 문제 제약 안에서 충분히 처리 가능한 규모입니다.

풀이 상단의 계산에는 다음 두 가지를 바로잡아야 합니다.

- `30C5`는 `13,600`이 아니라 **`142,506`**입니다.
- `query[i] in candidate`는 리스트를 최대 5칸 탐색하므로, 비교 연산을 자세히 셀 때는 `142,506 × 10 × 5 × 5` 정도입니다.

## 필수 수정

없습니다.

## 선택적 개선

### 1. 모든 조합을 메모리에 저장하지 않기

현재 `combination()`은 전체 후보를 `selected`에 모은 뒤 반환합니다. 후보를 하나씩 생성하면서 바로 검사하면 최대 142,506개의 리스트를 동시에 보관하지 않아도 됩니다. 파이썬 표준 라이브러리의 `itertools.combinations`는 조합을 순차적으로 꺼낼 수 있어 이 문제에 잘 맞습니다.

```python
from itertools import combinations

for candidate in combinations(range(1, n + 1), 5):
    # candidate를 즉시 검사
```

현재 코드도 제한 내에서는 통과 가능하므로 이는 정답을 위한 필수 수정이 아니라 공간 사용과 코드 길이를 줄이는 개선입니다.

### 2. 조건이 틀린 즉시 다음 후보로 넘어가기

현재는 한 질의가 틀려도 남은 질의를 모두 계산한 뒤 `answer == ans`를 비교합니다. 첫 불일치에서 검사를 중단하면 불필요한 연산을 줄일 수 있습니다.

```python
for candidate in combinations(range(1, n + 1), 5):
    for query, expected in zip(q, ans):
        count = sum(number in candidate for number in query)
        if count != expected:
            break
    else:
        result += 1
```

`for-else`에서 `else`는 반복문이 `break` 없이 끝났을 때만 실행되므로, 모든 질의를 통과한 후보만 셉니다.

### 3. 변수의 의미를 조금 더 직접 표현하기

후보 하나에 대한 질의별 계산 결과인 `answer`는 최종 답처럼 읽힐 수 있습니다. `matched_counts`처럼 바꾸면 `ans`와 비교하는 값이라는 의미가 더 분명해집니다. 다만 현재 변수명 때문에 이해가 어려운 수준은 아닙니다.

## 실행 검증

- 공식 예제 1: 실제 출력 `3`, 기대값 `3`
- 공식 예제 2: 실제 출력 `5`, 기대값 `5`
- `n=10`, `q=[[1,2,3,4,5]]`, `ans=[5]`: 실제 출력 `1`
- `n=10`, `q=[[1,2,3,4,5]]`, `ans=[0]`: 실제 출력 `1`
- `n=30`, 같은 질의 10개와 응답 10개가 모두 5인 경우: 실제 출력 `1`, 실행 시간은 현재 환경에서 약 `0.645초`

실행 테스트는 보조 근거이며, 정답 판정은 모든 조합을 열거하고 모든 질의의 교집합 크기를 검사한다는 논리로 확정했습니다. 실행 시간은 프로그래머스 서버와 다를 수 있습니다.

## 이 문제에서 읽어야 할 신호

- **“서로 다른 정수 5개가 오름차순”** → 순서를 고려하는 순열이 아니라 5개를 고르는 조합
- **`n <= 30`** → 먼저 최대 경우의 수 `30C5 = 142,506`을 계산하면 완전탐색이 가능하다는 판단
- **`m <= 10`, 각 질의 길이 5** → 후보 하나를 검증하는 비용이 매우 작음
- **“모든 시도 후 가능한 조합의 개수”** → 후보 하나가 모든 질의를 만족하는지 확인하는 필터링 문제
