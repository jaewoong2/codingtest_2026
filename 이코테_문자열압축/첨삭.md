# [이코테 / 프로그래머스] 문자열 압축 풀이 첨삭

## 총평
- **판정**: 정답 가능 (탈출 조건 추가 시)
- **핵심 이유**: 작성하신 인덱스 포인터 이동 수식은 완벽히 정상 동작합니다. 오직 `while True:` 안에서 슬라이싱 결과가 빈 문자열 `""`이 될 때 멈추어 주는 **탈출 조건(`if not current_word: break`)** 하나만 누락된 상태였습니다.

---

## 문제 핵심
- 문자열 `s`를 1개 이상 `len(s) // 2`개 이하의 단위로 잘라 압축했을 때, **가장 짧은 압축 문자열의 길이**를 구하는 문제입니다.
- **핵심 제약**: 문자열 길이가 최대 1,000으로 매우 작으므로, 모든 압축 단위(`step`)에 대해 일일이 압축해 보는 **완전 탐색(Brute Force)** 접근이 적합합니다.

---

## 작성하신 `while` 문 방식을 수정한 최종 정답 코드

```python
def solution(s):
    length = len(s)
    answer = length
    
    for step in range(1, length // 2 + 1):
        start, end = 0, step
        next_start, next_end = step, step + step
        word, value = "", 1
        
        while True:
            current_word = s[start:end]
            next_word = s[next_start:next_end]
            
            # 🎯 [핵심 탈출 조건] 처리할 현재 단어가 없으면 무한 루프 탈출
            if not current_word:
                break
            
            if current_word == next_word:
                value += 1
            else:
                if value > 1:
                    word = word + str(value) + current_word
                else:
                    word = word + current_word
                value = 1
            
            # 작성하신 올바른 인덱스 갱신 수식
            start, end = start + step, end + step
            next_start, next_end = start + step, end + step
        
        # 루프 탈출 후, 마지막으로 남아있던 단어 처리
        if value > 1:
            word = word + str(value) + current_word
        else:
            word = word + current_word
            
        answer = min(answer, len(word))
    
    return answer
```

## 🧠 구현 문제에서 탈출 조건(종료 조건)을 100% 잡아내는 4단계 사고법

구현 문제에서 탈출 조건 때문에 틀리거나 멘붕이 오는 것을 방지하기 위한 실전 훈련 공식입니다.

### 1단계: `while` 문을 치기 전에 '종착역 주석'부터 쓰기
- 코드를 완성하고 나서 탈출 조건을 생각하려고 하면 무조건 놓칩니다.
- `while` 키보드를 누르는 순간, **"이 루프는 변수가 어디까지 가야 멈추는가?"**를 주석으로 한 줄 적고 시작하세요.
  - 예: `# start가 s의 길이 이상이면 멈춘다!` 👉 `if start >= len(s): break`

### 2단계: '자투리가 남는 케이스(Edge Case)' 1개만 손으로 디버깅해보기 (30초)
- 머릿속으로 예쁘게 딱 떨어지는 케이스만 생각하면 실수합니다.
- 길이가 안 맞춰져서 자투리가 남는 작은 예시를 직접 손으로 3단계만 적어봅니다.
  - `s = "abcde"` (길이 5), `step = 2` 일 때:
    - 1회: `"ab"`, `"cd"`
    - 2회: `"cd"`, `"e"`
    - 3회: `"e"`, `""`
    - 4회: `""`, `""` 👈 **"아! current_word가 빈 문자열이 되는 순간이 오네!"**
- 손으로 써보는 순간 `if not current_word: break` 조건이 뇌에 직관적으로 박힙니다.

### 3단계: 파이썬 슬라이싱의 '스텔스 특성' 기억하기
- C++이나 Java는 범위를 넘어가면 `IndexOutOfBounds` 에러를 뿜어서 바로 알려줍니다.
- 하지만 **파이썬은 범위를 넘어가도 에러 없이 빈 값(`""`, `[]`)을 조용히 반환**합니다.
- 💡 **파이썬 공식**: `while` 루프 안에서 슬라이싱(`s[a:b]`)을 쓰면, 항상 **"슬라이싱 결과가 비어있는가?"**를 확인하는 탈출 조건이 필수입니다.

### 4단계: '끝을 아는 문제'는 `while` 대신 `for` 문으로 탈출 고민 없애기
- 전체 길이(`len(s)`)나 반복 횟수를 미리 알 수 있는 문제라면, 탈출 조건 고민이 필요 없는 **`for` 문**을 1순위로 선택하세요.
- `while` 문은 BFS 탐색처럼 **"몇 번 돌릴지 미리 계산이 불가능한 상태"**일 때 꺼내는 무기로 삼는 것이 좋습니다.
