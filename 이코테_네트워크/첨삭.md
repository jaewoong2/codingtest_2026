# [이코테 / 프로그래머스] 네트워크 풀이 첨삭

## 총평
- **판정**: **정답 (Correct)**
- **핵심 이유**: 
  1. 그래프의 **연결 요소(Connected Component)** 개수를 구하는 전형적인 탐색 문제를 깊이 우선 탐색(DFS) 알고리즘으로 명확히 해결했습니다.
  2. 2차원 인접 행렬 `computers`를 인접 리스트 `graphs`로 사전 전처리하여 직관적으로 탐색을 구성했습니다.
  3. 아직 방문하지 않은 노드를 만날 때마다 네트워크 수(`answer`)를 1 늘리고 해당 컴포넌트 전체를 방문 처리하는 흐름이 완전합니다.

---

## 문제 핵심
- $N$개의 컴퓨터(노드)와 간선 연결 정보가 2차원 배열 `computers`로 주어질 때, **서로 연결된 컴퓨터들의 묶음(연결 요소/Connected Component)의 총 개수**를 구해야 합니다.
- **핵심 제약**: $N \le 200$으로 매우 작은 그래프 크기입니다.
- **알고리즘 기법**: 무방향 그래프의 연결 요소 개수 세기 (DFS / BFS / Union-Find 모두 가능).

---

## 현재 접근법 평가

사용자께서 구현하신 접근법은 정석적인 그래프 탐색 과정입니다.

1. **인접 리스트 변환 (`graphs`)**: 2차원 인접 행렬을 다루기 편하도록 `graphs[i] = [j, ...]` 형태의 딕셔너리로 전처리.
2. **방문 체크 (`visited`)**: 딕셔너리의 `in` / `not in` 연산자로 방문 여부 제어.
3. **탐색 제어**: 0부터 $n-1$까지 순회하며 방문하지 않은 노드가 나오면 새로운 네트워크 시작(`answer += 1`)으로 간주 후 `dfs(i)` 호출.

---

## 복잡도 분석

- $V$: 노드(컴퓨터)의 수 ($N \le 200$)
- $E$: 간선(연결)의 수 (최대 $N^2$)
- **시간 복잡도**: $O(V + E)$ 혹은 인접 행렬 기준 $O(V^2)$
  - 전처리 과정: $O(V^2)$
  - DFS 탐색 과정: 각 노드와 간선을 최대 1번씩 방문하므로 $O(V + E)$
  - $N=200$일 때 $200^2 = 40,000$ 번 연산에 불과하여 실행 시간 약 0.001초 수준으로 매우 빠릅니다.
- **공간 복잡도**: $O(V + E)$
  - 인접 리스트 `graphs`와 방문 딕셔너리 `visited`를 위한 메모리입니다.

---

## 선택적 개선 제안 (가독성 & 표현 다듬기)

현재 코드도 완벽히 통과하지만, 아래 2가지를 다듬으면 코드가 훨씬 간결하고 관용적으로 개선됩니다.

### 1. `visited` 방문 체크 표현의 가독성
현재 코드의 `dfs` 내부에서는 `visited[next_node] = False`를 적고, 외부 루프에서는 `visited[i] = True`를 적었습니다.
파이썬 딕셔너리에서 `in` 연산자는 **키의 존재 여부**만 체크하므로 정답 처리에는 문제없지만, 보는 사람 입장에서 `False`와 `True`가 혼용되어 헷갈릴 수 있습니다.

* **개선안 A**: `set()` 집합 자료구조 활용 (`visited = set()`)
* **개선안 B**: 불리언 리스트 활용 (`visited = [False] * n`)

---

### 2. 인접 행렬 그대로 탐색하기 (전처리 생략)
`computers[i][j] == 1` 정보를 직접 탐색하면 별도의 `graphs` 딕셔너리 생성 과정(전처리)을 생략할 수 있어 코드가 단 10줄 정도로 줄어듭니다.

#### 💡 깔끔하게 다듬은 코드 예시
```python
def solution(n, computers):
    visited = [False] * n
    
    def dfs(node):
        visited[node] = True
        for neighbor in range(n):
            # 연결되어 있고 아직 방문하지 않은 컴퓨터 탐색
            if computers[node][neighbor] == 1 and not visited[neighbor]:
                dfs(neighbor)
    
    answer = 0
    for i in range(n):
        if not visited[i]:
            dfs(i)
            answer += 1 # 새로운 네트워크(연결 요소) 발견
            
    return answer
```

## 이 문제에서 읽어야 할 신호 (알고리즘 선택 가이드)

1. **"상호 간 연결되어 정보를 교환할 수 있다" + "네트워크의 개수"**
   - ⭐ **신호**: 그래프의 **연결 요소(Connected Component) 개수**를 구하라는 전형적인 요구사항입니다.

2. **$N \le 200$ 제약**
   - ⭐ **신호**: 그래프 탐색(DFS / BFS)이나 Disjoint Set (Union-Find)을 사용하면 최악의 경우에도 연산 횟수가 10만 회를 넘지 않는 쉬운 그래프 문제입니다.
