## 총평

- 판정: 오답
- 핵심 이유: 간선을 가중치 오름차순으로 처리하고 `find`로 사이클을 검사하는 크루스칼의 큰 흐름은 맞다. 하지만 `union`에서 루트가 아닌 원래 정점의 부모를 바꾸고 있어 연결 요소가 잘못 관리된다.
- 현재 샘플은 실제로 `159`가 나오지만, 샘플만으로 Union-Find가 올바르다고 판단할 수 없다.

## 현재 접근법

1. 모든 간선을 `(가중치, 정점 A, 정점 B)`로 저장한다.
2. 가중치가 작은 순서로 정렬한다.
3. 두 정점의 루트가 다르면 간선을 선택하고 두 집합을 합친다.
4. 선택한 간선의 가중치를 결과에 더한다.

이 순서는 크루스칼 알고리즘에 맞다.

## 정확성 검토

### 잘한 점

- 56행에서 가중치를 튜플의 첫 번째 값으로 두어 정렬 기준을 명확하게 만들었다.
- 61행에서 `find(a) != find(b)`를 확인한 뒤 간선을 선택하는 구조가 맞다.
- `find`에서 경로 압축을 사용하고 있다.

### 필수 수정: `union`은 루트의 부모를 변경해야 함

현재 코드:

```python
if parents_a > parents_b:
    parents[b] = parents_a
else:
    parents[a] = parents_b
```

`parents_a`, `parents_b`는 루트이지만 `a`, `b`는 루트라는 보장이 없다. 따라서 부모를 바꿀 때는 반드시 루트 인덱스를 사용해야 한다.

현재 방식의 최소 수정 방향은 다음과 같다.

```python
if parents_a > parents_b:
    parents[parents_b] = parents_a
else:
    parents[parents_a] = parents_b
```

더 일반적으로는 크기나 랭크를 저장해 작은 트리를 큰 트리 밑에 붙이는 방식이 좋다.

### 작은 반례

```text
3 3
1 2 6
1 3 8
2 3 28
```

정상적인 최소 신장 트리 비용은 `6 + 8 = 14`다.

현재 코드의 흐름:

1. `1-2` 선택: `parents[1] = 2`
2. `1-3` 처리: `find(1) = 2`, `find(3) = 3`인데 `parents[1] = 3`을 수행함
3. 이때 2번 루트는 여전히 2번이므로 1번과 2번의 연결 관계가 깨짐
4. `2-3`을 사이클이 아니라고 잘못 판단하고 28을 추가

따라서 현재 코드는 `42`를 계산하고, 기대값은 `14`다. 이 반례는 실제로 실행해 확인했다.

## 추가 확인 사항

### 연결되지 않은 그래프

모든 정점이 연결된다는 조건이 없다면 선택한 간선 수를 세어 `V - 1`개인지 확인해야 한다. 그렇지 않으면 최소 신장 포리스트의 비용을 반환하게 된다.

### 불필요한 코드

- 51행의 `graphs`는 이후 사용하지 않는다.
- `get()`과 `get_parents`도 사용하지 않는다.
- `int(1e19)`로 초기화한 뒤 다시 값을 채우므로 부모 배열은 처음부터 `[i for i in range(n + 1)]`로 만들 수 있다.

## 복잡도

`V`를 정점 수, `E`를 간선 수라고 하면 간선 정렬에 `O(E log E)`가 필요하다. 경로 압축과 union by size/rank를 함께 사용하면 Union-Find 연산은 거의 `O(1)`에 가까운 `O(α(V))`이고, 전체 복잡도는 `O(E log E)`가 지배적이다. 공간 복잡도는 간선 저장과 부모 배열을 포함해 `O(V + E)`다.

현재 코드는 경로 압축은 있지만 union by size/rank가 없으므로 트리 높이에 대한 보장이 약하다. 정답성의 우선 수정은 루트 인덱스를 부모로 연결하는 것이고, 이후 size/rank를 추가하면 된다.

## 필수 수정

1. `union`에서 `parents[a]`, `parents[b]` 대신 루트인 `parents_a`, `parents_b`를 사용한다.
2. 그래프가 비연결일 수 있으면 선택한 간선 수를 확인한다.

## 선택적 개선

1. `graphs`, `get`, `get_parents`를 제거한다.
2. 부모 배열을 간단하게 초기화한다.
3. union by size 또는 rank를 추가한다.
4. 함수명을 `union_find` 대신 `make_union_find`처럼 역할이 드러나게 바꿀 수 있다.

## 다음 문제를 위한 체크포인트

Union-Find에서 `find(x)`는 “x가 속한 집합의 대표 번호”를 반환한다. 두 집합을 합칠 때는 원래 정점이 아니라 반드시 이 대표 번호들의 부모를 연결해야 한다.
