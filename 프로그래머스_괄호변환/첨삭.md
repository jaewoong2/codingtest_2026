# [프로그래머스 60058] 괄호 변환 풀이 첨삭

## 총평

- **판정**: 정답
- **핵심 이유**: 문제가 제시한 재귀 변환 절차를 그대로 구현했습니다. `detatch()`로 이미 더 나눌 수 없는 가장 짧은 균형 문자열 `u`를 만들고, `u`의 올바름 여부에 따라 3단계와 4단계를 정확히 분기합니다.

## 문제 핵심

- 입력 `p`는 `'('`, `')'`로만 이루어지며, 여는 괄호와 닫는 괄호의 개수가 같은 **균형잡힌 괄호 문자열**입니다.
- 길이는 2~1,000의 짝수이며, 이미 올바른 괄호 문자열이면 그대로 반환합니다.
- 문제에 주어진 절차대로 `w`를 업데이트해 최종 올바른 괄호 문자열을 만듭니다.

특히 **균형잡힌**은 여는 괄호와 닫는 괄호의 수만 같다는 뜻이고, **올바른**은 왼쪽에서 읽었을 때 닫는 괄호가 여는 괄호보다 앞서지 않는 뜻입니다.

## 현재 접근법

1. `check_balance(w)`로 `'('`와 `')'`의 개수가 같은지 확인합니다.
2. `detatch(w)`는 앞에서부터 가장 짧은 균형 접두사 `u`를 찾고, 나머지를 `v`로 나눕니다.
3. `check_correct(u)`로 `u`가 올바른 괄호 문자열인지 판단합니다.
4. 올바르면 `u + check(v)`를 반환하고, 아니면 `'(' + check(v) + ')' + four_four(u)`를 반환합니다.
5. `four_four(u)`는 `u`의 첫·마지막 문자를 제거한 후 남은 괄호를 모두 뒤집니다.

함수들을 문제 절차의 각 단계에 맞게 나누어 두어서, 재귀의 흐름을 따가기 좋습니다.

## 정확성 및 반례

반례를 발견하지 못했습니다.

- `detatch()`는 길이 2부터 앞에서부터 확인하다가 처음 균형이 되는 접두사를 반환합니다. 균형 문자열의 길이는 반드시 짝수이므로 `range(2, len(w), 2)`로 짝수 위치만 검색해도 누락이 없습니다. 항상 전체 문자열이 하나의 `u`인 경우도 마지막 `return w, ""`으로 처리됩니다.
- `check_correct()`의 스택은 `(`을 쌓고 맞는 `)`을 만나면 꾸내 검색합니다. 이 함수는 닫는 괄호가 스택이 빈 상태에서 나와도 즉시 `False`를 반환하지는 않습니다. 그러나 호출될 때의 `u`는 항상 균형잡힌 문자열입니다. 균형 문자열에서 일찍 남는 `)`가 있으면, 전체 개수를 맞추기 위해 이후에 짝이 맞지 않는 `(`이 동일하게 남겠습니다. 결국 스택이 비지 않아 `False`가 반환되므로, 문제의 입력 범위에서 정확합니다.
- `u`가 올바르면 문제의 3단계와 같이 `u` 뒤에 재귀 변환한 `v`를 붙입니다.
- `u`가 올바르지 않으면 문제의 4-1~4-4단계와 같이 양쪽에 `(`, `)`를 붙이고, 내부 문자들을 뒤집니다.
- 매 재귀에서 `u`가 비어 있지 않고 `v`는 더 짧아지므로, 기저 조건 `w == ""`에 반드시 도달합니다.

따라서 이 코드는 문제에서 지정한 변환 결과를 정확히 만듭니다.

## 복잡도

`N`을 입력 문자열의 길이라고 하겠습니다. 제약은 `N <= 1,000`입니다.

- `detatch()`는 접두사를 단계적으로 만들고 매번 `check_balance()`를 호출합니다. 한 호출에서 최악의 경우 `O(N^2)`입니다.
- 재귀 단계에서 문자열 슬라이싱, 뒤집기, 연결이 수행되므로 전체 **시간 복잡도는 `O(N^2)`**으로 볼 수 있습니다.
- 재귀 깊이는 `u`의 최소 길이가 2이므로 최대 `N / 2`입니다. `N = 1,000`에서 500이며, 제출 환경의 기본 파이썬 재귀 한도(1000)에 여유가 있습니다.
- 스택과 재귀 호출, 생성되는 문자열을 포함한 공간은 실질적으로 `O(N^2)`까지 사용할 수 있으나, `N = 1,000`이므로 충분히 작은 규모입니다.

## 필수 수정

없습니다.

## 선택적 개선

- `detatch`는 일반적으로 `detach`로 쓰는 철자입니다. 더 구체적으로는 `split_balanced`라고 이름 짓면 역할이 분명해집니다.
- `four_four()`는 이름만으로 동작을 알 수 없습니다. `flip_inner_parentheses()` 같이 담는 데이터와 동작을 나타내는 이름이 좋습니다.
- 반복문에서 `if c == "(": ...; if c == ")": ...`처럼 상호 배타적인 조건을 연속으로 쓰기보다 `if ... else ...`로 쓰면 의도가 더 분명합니다.
- 일반적인 괄호 판별 함수로 재사용할 예정이면, `check_correct()`에서 빈 스택에서 `)`를 만나는 순간 즉시 `False`를 반환하면 입력이 균형이지 않아도 정확히 판단할 수 있습니다. 현재 문제에서는 `u`가 균형이므로 필수 수정은 아닙니다.

## 실행 검증

- 공식 예제 3건의 **실제 출력**이 각각 `"(()())()"`, `"()"`, `"()(())()"`로 기대값과 일치했습니다.
- 길이 2~16의 모든 균형 입력 문자열 **17,576건**을 문제 절차를 직접 구현한 독립 기준 풀이와 교차 검증했고, 모두 일치했습니다.
- 제한 최대 길이인 `"()" * 500`도 정상 반환됨을 확인했습니다.
- 실행 테스트는 보조 근거이며, 정답 판정은 문제의 재귀 절차와 일치한다는 논리로 확정했습니다.
