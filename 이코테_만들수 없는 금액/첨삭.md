# 이코테 만들 수 없는 금액 첨삭

## 총평

- **판정: 정답**
- 동전을 오름차순으로 정렬한 뒤, 현재까지 끊기지 않고 만들 수 있는 금액의 다음 값을 `target`으로 관리한 접근이 정확합니다.
- 저장소의 `input.txt`로 실행한 결과는 `8`이었고, 작은 조합을 전부 비교하는 검증에서도 같은 결과를 확인했습니다.

## 문제 핵심

동전들을 원하는 만큼 각각 최대 한 번 사용해서 만들 수 없는 **가장 작은 양의 정수**를 구하는 문제입니다.

예를 들어 `1 1 2 3 9`가 있으면 `1`부터 `7`까지는 만들 수 있지만 `8`은 만들 수 없습니다. 따라서 가장 작은 만들 수 없는 금액은 `8`입니다. `9` 동전은 `8`보다 크기 때문에 `8`을 만드는 데 사용할 수 없습니다.

## 현재 접근법

코드의 핵심은 다음과 같습니다.

```python
target = 1

for number in array:
    if number > target:
        break
    target += number
```

`target`의 의미는 다음과 같습니다.

> 지금까지 확인한 동전들로 `1`부터 `target - 1`까지는 모두 만들 수 있다.

동전 `number`가 `target`보다 크면 `target`을 만들 동전이 없습니다. 이미 확인한 동전으로는 `target`보다 작은 금액까지만 만들 수 있고, 이후 동전들은 정렬되어 있으므로 더 큰 동전뿐입니다. 따라서 그 순간의 `target`이 답입니다.

반대로 `number <= target`이면 기존에 만들 수 있던 금액 범위와 새 동전을 사용한 금액 범위가 이어집니다.

- 기존 범위: `1 ~ target - 1`
- 새 동전으로 만들 수 있는 범위: `number ~ number + target - 1`
- `number <= target`이므로 두 범위가 끊기지 않음
- 새로운 범위: `1 ~ target + number - 1`

그래서 `target += number`로 갱신합니다.

## 예시 추적

입력 동전이 `1 1 2 3 9`일 때:

| 동전 | 처리 전 `target` | 판단 | 처리 후 `target` | 만들 수 있다고 보장되는 범위 |
|---:|---:|---|---:|---|
| - | 1 | 시작 | 1 | 없음 |
| 1 | 1 | `1 <= 1` | 2 | `1` |
| 1 | 2 | `1 <= 2` | 3 | `1~2` |
| 2 | 3 | `2 <= 3` | 5 | `1~4` |
| 3 | 5 | `3 <= 5` | 8 | `1~7` |
| 9 | 8 | `9 > 8` | 8 | `1~7` |

따라서 이 입력의 답은 `8`입니다. `9` 동전은 `8`을 만들 수 없게 된 뒤에 처음 등장하므로, `8`은 만들 수 없는 가장 작은 금액입니다.

## 정확성

정렬이 중요한 이유는 `number > target`인 순간 이후의 모든 동전도 `target`보다 크거나 같다는 것을 보장하기 위해서입니다.

현재 코드의 `break` 조건은 올바릅니다. 예를 들어 동전이 `1 2 5`라면:

- `1` 처리 후 `target = 2`
- `2` 처리 후 `target = 4`
- 다음 `5`는 `target = 4`보다 큼
- `4`는 만들 수 없으므로 답은 `4`

이때 `5`를 사용해도 `4`를 만들 수 없고, 그 뒤에 더 큰 동전만 남아 있으므로 계속 확인할 필요가 없습니다.

## 복잡도

동전 개수를 `N`이라고 하면:

- 정렬: `O(N log N)`
- 정렬 후 한 번 순회: `O(N)`
- 전체 시간 복잡도: `O(N log N)`
- 정렬과 입력 배열에 필요한 공간: `O(N)`

## 필수 수정

알고리즘상 필수 수정은 없습니다.

## 선택적 개선

현재 코드의 실행 환경 보조 부분은 제출 코드에서는 제거하는 편이 안전합니다.

```python
if os.path.exists(os.path.join(os.path.dirname(__file__), "input.txt")):
    sys.stdin = open(os.path.join(os.path.dirname(__file__), "input.txt"), "r")
```

같은 폴더에 `input.txt`가 있으면 표준 입력보다 그 파일을 먼저 읽습니다. 로컬 테스트에는 편하지만, 제출할 때 오래된 테스트 파일을 함께 둔 실수를 숨길 수 있습니다. 알고리즘과는 무관한 편의 기능입니다.

또한 다음처럼 작성하면 입력 개수가 `n`이라는 점이 코드에 드러납니다.

```python
array = list(map(int, input().split()))
```

## 이 문제에서 읽어야 할 신호

- “가장 작은 만들 수 없는 금액” → 답이 어디서 끊기는지 추적
- 동전의 개수가 많음 → 모든 부분집합을 직접 확인하면 너무 큼
- 동전은 한 번씩만 사용 → 지금까지의 만들 수 있는 금액 범위를 이용
- 오름차순 정렬 → 작은 동전부터 범위를 확장하는 그리디

## 다음 문제를 위한 체크포인트

1. 현재까지 만들 수 있는 금액이 `1 ~ target - 1`이라고 가정한다.
2. 다음 숫자가 `target`보다 크면 `target`은 절대 만들 수 없다.
3. 다음 숫자가 `target` 이하이면 범위가 이어지므로 `target += number` 한다.
4. 이 판단을 하려면 반드시 숫자를 오름차순으로 본다.

이 문제의 핵심 문장은 이것 하나입니다.

> **현재까지 `1 ~ target - 1`을 만들 수 있는데, 다음 동전이 `target`보다 크면 `target`이 정답이다.**
