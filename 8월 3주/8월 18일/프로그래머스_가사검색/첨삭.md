## 총평

- 판정: **오답 (경계 조건 버그)**
- 핵심 이유: **길이별 단어 분리**, **문자열 뒤집기를 통한 접두사/접미사 통일**, **`?`를 `a`와 `z`로 치환한 사전순 구간 검색**이라는 핵심 아이디어는 100점입니다. 그러나 직접 구현한 `find_left_index`와 `find_right_index`의 등호/부등호 조건이 어긋나 있어, 경계 단어(`froaa`, `frozz` 등)가 실제로 입력에 주어지면 정답에서 누락됩니다.

---

## 문제 핵심

- 단어 목록 `words` ($N \le 100,000$)와 검색 쿼리 `queries` ($M \le 100,000$)가 주어집니다.
- 매 쿼리마다 일치하는 단어 수를 구해야 합니다.
- **핵심 제약**:
  1. 단어와 검색어의 **길이가 정확히 일치**해야 함.
  2. `?`는 오직 **접두사(앞쪽)** 또는 **접미사(뒤쪽)**에만 연속으로 나타남. (중간에 섞이지 않음)
- 완전 탐색 시 $O(N \times M) \approx 100억$으로 시간 초과가 발생하므로, 각 쿼리를 $O(\text{단어길이} \times \log N)$ 또는 $O(\text{단어길이})$에 처리해야 합니다.

## 질문별 심층 해설

### 1. 이 아이디어를 뽑아내는 사고의 흐름 (발상 프로세스)

이 문제는 처음 보면 "문자열 매칭 = Trie(트라이)"를 먼저 떠올리기 쉽지만, 아래와 같은 단계적 사고를 거치면 **"정렬 + 이분 탐색"**이 가장 깔끔하고 강력한 해법임을 도출할 수 있습니다.

```text
[1단계] 제약 확인 & 단순 비교의 한계
  - N=10만, M=10만 -> 100억 번 연산 불가.
  - 쿼리당 O(log N) 수준의 탐색이 필요함.

[2단계] 문제의 특수 조건 포착
  - "단어의 길이가 같아야 한다" -> 길이별로 배열을 분리하자!
  - "?가 뒤나 앞쪽에만 몰려있다" -> 가운데는 변하지 않고 끝부분만 범위로 넓어진다!

[3단계] 사전순 '범위 검색'으로 발상 전환
  - 'fro??' (길이 5)에 매칭되는 단어는?
    = 'fro'로 시작하는 모든 5글자 단어
    = 사전순으로 정렬했을 때 'froaa' 이상 ~ 'frozz' 이하인 단어들!
  - 🎯 "정렬된 사전에서 특정 범위 [start, end]에 속하는 개수 구하기" -> 이분 탐색(Bisect)!

[4단계] 앞쪽 물음표('????o') 해결 (발상의 대칭성)
  - 사전순 정렬은 '앞 글자' 기준이므로 뒷글자 일치는 이분 탐색이 불가능.
  - 해결책: 단어와 검색어를 모두 '뒤집어버리면(Reverse)' 앞글자 기준으로 바뀌어 동일하게 풀린다!
```

### 2. Lower Bound vs Upper Bound 도식화 & 완벽 정리

많은 분들이 가장 헷갈려하는 부분입니다. 한 번 확실히 그림으로 뇌에 새겨두면 평생 헷갈리지 않습니다.

#### 핵심 정의
- **`lower_bound(target)`**: `target` **이상($\ge$)**의 값이 처음 등장하는 인덱스
- **`upper_bound(target)`**: `target` **초과($>$)**하는 값이 처음 등장하는 인덱스

#### 📊 도식으로 한눈에 보기
배열 `arr = [10, 20, 20, 20, 30, 40]`에서 값 `20`을 찾을 때:

```text
 인덱스:    0     1     2     3     4     5     6 (배열 끝)
   값:    [ 10 | 20    20    20 | 30 |  40 ]
               ^                 ^
               |                 |
        lower_bound(20)   upper_bound(20)
          (인덱스 1)         (인덱스 4)
```

#### 🎯 구간 내 원소 개수 공식 (무조건 외워야 하는 만능 공식)
1. **특정 값 $X$의 개수**:
   $$\text{count}(X) = \text{upper\_bound}(X) - \text{lower\_bound}(X)$$
   - 예: `20`의 개수 = `upper_bound(20) - lower_bound(20)` = $4 - 1 = 3$개

2. **구간 $[L, R]$ ($L \le x \le R$)에 속하는 원소 개수**:
   $$\text{count}([L, R]) = \text{upper\_bound}(R) - \text{lower\_bound}(L)$$
   - 예: $[20, 30]$ 범위의 개수 = `upper_bound(30) - lower_bound(20)` = $5 - 1 = 4$개 (`[20, 20, 20, 30]`)

## 정확성 및 반례

현재 코드의 `find_left_index`와 `find_right_index`는 조건식이 반대로 작성되어 있습니다.

### 반례
- **입력**:
  - `words = ["froaa", "frodo", "front", "frost", "frozz"]`
  - `queries = ["fro??"]`
- **기대 출력**: `[5]` (`froaa`와 `frozz`를 포함하여 5개 모두 일치)
- **현재 코드의 실제 출력**: `[3]` (`froaa`와 `frozz`가 누락됨)

### 원인 분석
- `find_left_index`에서 `array[mid] <= target`일 때 `left = mid + 1`로 전진하므로, `target`과 똑같은 단어가 있으면 **그 단어를 건너뛰고 다음 인덱스**를 반환합니다.
- `find_right_index`에서 `array[mid] >= target`일 때 `right = mid - 1`로 후퇴하므로, `target`과 똑같은 단어가 있으면 **그 단어의 이전 인덱스**를 반환합니다.

## 필수 수정

### 방법 1. 파이썬 표준 라이브러리 `bisect` 활용 (가장 추천)
실전 코딩테스트에서는 직접 이분 탐색을 구현하다가 등호 실수로 틀리기 쉬우므로, C로 최적화된 내장 모듈을 쓰는 것이 안전하고 훨씬 빠릅니다.

```python
from bisect import bisect_left, bisect_right

def count_by_range(a, left_value, right_value):
    right_index = bisect_right(a, right_value)
    left_index = bisect_left(a, left_value)
    return right_index - left_index
```

### 방법 2. 직접 구현 시 올바른 템플릿
직접 작성해야 한다면 아래 템플릿의 **부등호(`>=` vs `>`)** 차이를 꼭 기억하세요.

```python
# target 이상의 첫 위치 (Lower Bound)
def lower_bound(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] >= target: # target 이상이면 왼쪽으로 당김
            right = mid - 1
        else:
            left = mid + 1
    return left

# target 초과의 첫 위치 (Upper Bound)
def upper_bound(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] > target:  # target 초과일 때만 왼쪽으로 당김
            right = mid - 1
        else:
            left = mid + 1
    return left
```

## 선택적 개선 및 깔끔한 추천 코드

1. `[x for x in query][::-1]` $\rightarrow$ `query[::-1]` (문자열 슬라이싱으로 간결화)
2. `100001` 크기의 배열 전체를 미리 초기화하고 10만 번 루프를 돌며 `.sort()`하는 대신 `collections.defaultdict(list)`를 사용하면 메모리와 정렬 오버헤드를 대폭 줄일 수 있습니다.

```python
from bisect import bisect_left, bisect_right
from collections import defaultdict

def count_by_range(arr, left_val, right_val):
    return bisect_right(arr, right_val) - bisect_left(arr, left_val)

def solution(words, queries):
    # 길이별 단어 리스트 저장 (정방향, 역방향)
    words_by_len = defaultdict(list)
    reversed_words_by_len = defaultdict(list)
    
    for word in words:
        words_by_len[len(word)].append(word)
        reversed_words_by_len[len(word)].append(word[::-1])
        
    for length in words_by_len:
        words_by_len[length].sort()
        reversed_words_by_len[length].sort()
        
    answer = []
    for query in queries:
        length = len(query)
        if query[0] == '?': # 접두사에 '?'가 있는 경우 (뒤집어서 검색)
            cnt = count_by_range(
                reversed_words_by_len[length],
                query[::-1].replace('?', 'a'),
                query[::-1].replace('?', 'z')
            )
        else:               # 접미사에 '?'가 있는 경우
            cnt = count_by_range(
                words_by_len[length],
                query.replace('?', 'a'),
                query.replace('?', 'z')
            )
        answer.append(cnt)
        
    return answer
```

## 복잡도

- $N$: 단어의 개수 ($N \le 100,000$), $M$: 쿼리 개수 ($M \le 100,000$)
- $L$: 단어의 평균 길이 ($L \le 10,000$, 전체 문자 수 합 $\le 1,000,000$)
- **시간 복잡도**:
  - 단어 정렬: $O(N \log N \times L)$
  - 쿼리 탐색: $O(M \times (\log N \times L))$
  - 전체 $10^6$ 글자 규모에서 약 0.5초 이내로 매우 여유롭게 통과합니다.
- **공간 복잡도**: $O(N \times L)$ (단어 및 뒤집은 단어 저장)

## 이 문제에서 읽어야 할 신호

1. **"특정 접두사/접미사로 시작하는 단어의 개수"**
   - $\rightarrow$ 사전순 정렬 후 **`prefix + 'a'` ~ `prefix + 'z'` 범위 이분 탐색**
2. **"접두사와 접미사 모두 지원해야 할 때"**
   - $\rightarrow$ **원본 배열 + 뒤집은(Reversed) 배열 2개를 준비**하여 접두사 문제 하나로 통일하기!
