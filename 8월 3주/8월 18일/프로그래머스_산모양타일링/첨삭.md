## 총평

- 판정: **정답**
- 핵심 이유: 인접한 블록 간의 '공유 삼각형' 유무에 따라 상태를 나누고, `(전체 - 오른쪽) * 비공유 경우의 수 + 오른쪽 * 공유 경우의 수`라는 매우 영리하고 정확한 점화식을 도출했습니다. $O(N)$ 시간 및 공간 복잡도로 효율성까지 완벽합니다.

---

## 문제 핵심

- $2N+1$개의 정삼각형으로 이루어진 사다리꼴 위에, 특정 위치마다 윗쪽 삼각형(`tops`)이 붙어 산 모양을 이룹니다.
- 채울 수 있는 타일은 **작은 정삼각형(1칸)**과 **마름모(2칸 붙은 타일)**입니다.
- $N$이 최대 $100,000$이므로 모든 경우를 시도하는 완전 탐색($O(2^N)$ 이상)은 불가능하며, $O(N)$의 **동적 계획법(DP)**으로 해결해야 합니다.

---

## 현재 접근법 분석

사용자께서는 산 모양을 $N$개의 기본 블록(사다리꼴 단위)으로 나누어 보았습니다.

- `dp[i][0]`: $i$번째 블록까지 완성하는 **전체 경우의 수**
- `dp[i][1]`: $i$번째 블록이 다음 블록과의 **공유 삼각형(오른쪽 아래)을 마름모로 덮은 경우의 수**

### 도출한 점화식의 원리

- 이전 단계에서 오른쪽 삼각형을 덮지 않은 경우의 수 = `dp[i-1][0] - dp[i-1][1]`
- 이전 단계에서 오른쪽 삼각형을 이미 덮은 경우의 수 = `dp[i-1][1]`
- `tops[i] == 1` (윗 삼각형 있음):
  - 비공유 상태에서 진입 시 이번 블록을 채우는 경우의 수: **4가지**
  - 공유 상태에서 진입 시 이번 블록을 채우는 경우의 수: **3가지**
  - $\rightarrow dp[i][0] = (\text{비공유} \times 4 + \text{공유} \times 3) \pmod{10007}$
- `tops[i] == 0` (윗 삼각형 없음):
  - 비공유 상태에서 진입 시 이번 블록을 채우는 경우의 수: **3가지**
  - 공유 상태에서 진입 시 이번 블록을 채우는 경우의 수: **2가지**
  - $\rightarrow dp[i][0] = (\text{비공유} \times 3 + \text{공유} \times 2) \pmod{10007}$
- 다음 블록으로 뻗어나가는 경우의 수는 언제나 이전 단계의 전체 경우의 수와 같습니다:
  - $\rightarrow dp[i][1] = dp[i-1][0]$

> 💡 **피드백**: 전체에서 부분집합을 빼서 비공유 상태를 구하는 아이디어는 매우 독창적이며 수학적으로 완벽합니다.

## 다른 사람들의 접근법 비교

다른 사람들의 풀이도 본질적으로는 **"인접 블록 간의 경계(공유 삼각형) 상태를 어떻게 표현할 것인가"**로 귀결됩니다.

### 방식 1. 가장 대중적인 2상태 분할 DP (공유/비공유를 분리 관리)

사용자 풀이가 `[전체, 공유]`를 저장했다면, 가장 일반적인 정석 풀이는 `[공유, 비공유]`를 각각 저장합니다.

- `a[i]`: $i$번째 블록의 오른쪽을 마름모로 덮은 경우
- `b[i]`: $i$번째 블록의 오른쪽을 마름모로 덮지 않은 경우

```python
# tops[i] == 1 일 때
a[i] = (a[i-1] + b[i-1]) % MOD
b[i] = (2 * a[i-1] + 3 * b[i-1]) % MOD

# tops[i] == 0 일 때
a[i] = (a[i-1] + b[i-1]) % MOD
b[i] = (a[i-1] + 2 * b[i-1]) % MOD
```

- 사용자의 점화식과 변수 치환 관계일 뿐 완벽히 동일한 구조입니다. ($dp[i][0] = a[i] + b[i]$, $dp[i][1] = a[i]$)

### 방식 2. 공간 최적화 DP ($O(1)$ 메모리)

$i$번째 계산에는 오직 $i-1$번째 값만 필요하므로, 2차원 배열 대신 두 개의 변수만 유지하며 갱신합니다.

```python
def solution(n, tops):
    MOD = 10007
    a, b = 1, (3 if tops[0] == 1 else 2)

    for top in tops[1:]:
        new_a = (a + b) % MOD
        new_b = ((2 * a + 3 * b) if top == 1 else (a + 2 * b)) % MOD
        a, b = new_a, new_b

    return (a + b) % MOD
```

## 이런 문제가 바로 안 떠오를 때: 타일링 DP를 뚫는 4단계 사고 공식

타일링 문제가 막히는 이유는 "머리가 굳어서"가 아니라, **"복잡한 모양을 어디서 잘라야 하는지"** 기준이 없기 때문입니다.
어떤 타일링/격자 문제든 아래 **4단계 공식**을 그대로 적용하면 풀이의 틀이 바로 잡힙니다.

```text
[1단계] 최소 반복 단위(블록)로 쪼갠다.
   ↓
[2단계] 블록 간의 '간섭(침범)'이 일어나는 경계선을 찾는다.
   ↓
[3단계] "경계를 침범했는가(1) / 안 했는가(0)"로 상태(State)를 나눈다.
   ↓
[4단계] N=1 블록을 직접 손으로 그리며 화살표(전이 계수)를 채운다.
```

### 단계별 상세 가이드

1. **1단계: 반복되는 최소 패턴 찾기**
   - 전체 산 모양을 보지 말고, "위로 솟은 삼각형 1개 + 아래 역삼각형 1개 + 오른쪽 정삼각형 1개"가 $N$번 반복되고 있음을 캐치합니다.
2. **2단계: "왜 블록별 경우의 수를 그냥 곱하면 안 될까?" (간섭 찾기)**
   - 만약 블록 1과 블록 2가 완전히 분리되어 있다면 경우의 수는 단순히 $(4 \times 3 \times 4 \dots)$ 곱셈일 것입니다.
   - 곱셈으로 안 끝나는 유일한 이유는 **"블록과 블록 사이에 걸치는 타일(오른쪽 마름모)"**이 존재하기 때문입니다.
3. **3단계: 간섭하는 지점만 상태로 정의하기**
   - 이전 블록 내부가 어떻게 채워졌는지는 알 필요가 없습니다! (DP의 무기억성)
   - 오직 **"이전 블록이 내 영역으로 마름모를 뻗었는가? (YES / NO)"** 이것만 알면 이번 블록을 채울 수 있습니다.
4. **4단계: $N=1$일 때 손으로 그려서 경우의 수 세기**
   - 이전 블록이 안 뻗었을 때($NO$):
     - `top=1`: 전체 채우기 4가지 (안 뻗기 3가지 + 다음으로 뻗기 1가지)
     - `top=0`: 전체 채우기 3가지 (안 뻗기 2가지 + 다음으로 뻗기 1가지)
   - 이전 블록이 뻗었을 때($YES$):
     - `top=1`: 전체 채우기 3가지 (안 뻗기 2가지 + 다음으로 뻗기 1가지)
     - `top=0`: 전체 채우기 2가지 (안 뻗기 1가지 + 다음으로 뻗기 1가지)

이 4단계를 거치면 점화식이 억지로 외우는 공식이 아니라 **단순한 표 채우기**로 바뀝니다.

---

## 정확성 및 복잡도

- **시간 복잡도**: $O(N)$
  - 반복문이 $N-1$번 돌며 각 단계에서 단순 사칙연산만 수행하므로 약 $100,000$번 연산 ($0.05$초 이내 완료).
- **공간 복잡도**: $O(N)$
  - 크기 $N \times 2$의 배열 사용. ($O(1)$로 최적화 가능)

## 선택적 개선

1. **모듈로 연산과 음수 처리 (타 언어 호환 팁)**:
   - 파이썬의 `%` 연산자는 음수를 양수 나머지로 정상 변환해주므로 파이썬에서는 `(dp[i-1][0] - dp[i-1][1]) % 10007`이 항상 안전합니다.
   - 단, C++이나 Java에서는 음수 모듈로 연산 시 음수가 반환되므로 `(dp[i-1][0] - dp[i-1][1] + 10007) % 10007` 처럼 `+ MOD`를 해주는 습관을 들이면 좋습니다.
2. **공간 최적화**:
   - $N$이 최대 10만일 때는 $O(N)$ 리스트도 메모리 초과가 나지 않지만, 변수 2개로 줄이면 메모리를 더욱 절약할 수 있습니다.

## 이 문제에서 읽어야 할 신호

1. **"크기 $N$의 타일을 겹치지 않게 덮는 경우의 수" + "$N \le 100,000$"**
   - $\rightarrow$ $O(N)$ 선형 시간의 **1차원/2상태 DP**가 100%입니다.
2. **"인접한 두 구간이 특정 영역을 공유함"**
   - $\rightarrow$ 그 공유 영역을 **"이전 단계가 덮었음 / 안 덮었음"**의 2가지 상태로 분기하는 신호입니다.
