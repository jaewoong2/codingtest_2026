# 이코테 모험가 길드 첨삭

## 총평

- **판정: 오답**
- 정렬 후 공포도가 낮은 사람부터 그룹을 만들겠다는 방향은 맞습니다.
- 하지만 현재 코드는 그룹을 완성하는 시점에 현재 모험가를 제대로 포함하지 않고, 마지막 그룹을 처리하지 못할 수 있습니다.
- 시간 복잡도는 충분하지만, 그룹 인원과 그룹 완성 조건을 관리하는 로직을 수정해야 합니다.

## 문제 핵심

공포도가 `X`인 모험가는 자신을 포함해 **최소 X명 이상**인 그룹에 들어가야 합니다.

모든 모험가를 반드시 사용할 필요는 없으며, 만들 수 있는 그룹 수의 최댓값을 구해야 합니다.

예를 들어 공포도가 다음과 같다면:

```text
1 2 2 3 3 4 4
```

앞에서부터 그룹을 만들면서 현재 그룹 인원이 현재 공포도 이상이 되는 순간 그룹을 확정하면 됩니다.

## 현재 풀이의 접근법

현재 코드는 다음 순서로 동작합니다.

1. 공포도를 오름차순으로 정렬합니다.
2. `minimum`에 현재 그룹에서 가장 큰 공포도를 저장하려고 합니다.
3. `length`로 현재 그룹의 인원 수를 관리합니다.
4. `length == minimum`이면 그룹 수를 증가시킵니다.

정렬을 먼저 한 점과 낮은 공포도의 모험가부터 처리하려는 생각은 적절합니다.

## 정확성 및 반례

### 최소 반례

입력:

```text
2
1 1
```

기대 출력:

```text
2
```

공포도가 1인 모험가는 혼자서도 그룹을 만들 수 있으므로 `[1]`, `[1]` 두 그룹을 만들 수 있습니다.

현재 코드의 실제 출력:

```text
1
```

### 오류 흐름

현재 초기값은 다음과 같습니다.

```python
minimum = -1
length = 1
```

첫 번째 `1`을 처리하면:

```text
minimum = 1
length == minimum  → 그룹 1개 생성
length = 0
```

두 번째 `1`을 처리하면:

```text
minimum = 1
length < minimum  → length = 1
```

반복문이 끝났기 때문에 두 번째 사람으로 만든 그룹을 확인하지 못합니다.

즉, 현재 코드는 **현재 사람을 그룹 인원에 포함하기 전에 그룹 완성 여부를 검사하는 구조**입니다.

### 더 큰 반례

입력:

```text
6
2 2 3 3 4 4
```

기대 그룹:

```text
[2, 2]
[3, 3, 4, 4]
```

기대 출력:

```text
2
```

현재 코드의 실제 출력:

```text
1
```

두 번째 그룹은 인원이 4명이고 가장 큰 공포도도 4이므로 유효합니다. 하지만 현재 코드는 마지막 `4`를 처리한 뒤 `length`가 4가 되고 반복문이 종료되어 그룹을 증가시키지 못합니다.

## 핵심 수정 방향

현재 모험가를 먼저 그룹에 포함한 뒤, 그룹 조건을 확인해야 합니다.

```python
count += 1

if count >= fear:
    groups += 1
    count = 0
```

정렬되어 있으므로 현재 `fear`는 지금 그룹에서 가장 큰 공포도입니다. 따라서 `count >= fear`이면 현재 그룹의 모든 모험가가 조건을 만족합니다.

## 추천 구현

현재 코드의 구조를 단순하게 바꾸면 다음과 같습니다.

```python
def solution():
    n = int(input())
    users = sorted(map(int, input().split()))

    groups = 0
    count = 0

    for fear in users:
        count += 1

        if count >= fear:
            groups += 1
            count = 0

    return groups
```

`n`은 입력 형식을 확인하는 역할만 하며, `users`의 길이가 항상 `n`이라는 조건이라면 반복문에서 직접 사용하지 않아도 됩니다.

## 점화식이 아니라 그리디인 이유

이 문제는 현재 그룹을 가능한 한 빨리 확정하는 것이 유리합니다.

공포도가 오름차순으로 정렬되어 있으므로:

```text
현재까지의 모든 공포도 <= 현재 공포도
```

입니다.

따라서 현재 인원이 `fear` 이상이 되는 순간 그룹을 만들면 현재 그룹은 유효합니다. 여기서 더 기다리면 사람을 더 사용하게 되므로 남은 사람으로 만들 수 있는 그룹 수가 줄어들 수 있습니다.

즉:

```text
정렬
→ 한 명씩 현재 그룹에 추가
→ 현재 그룹 인원이 현재 공포도 이상이면 즉시 그룹 확정
```

이 방식이 그룹 수를 최대로 만듭니다.

## 복잡도

`N`을 모험가 수라고 하겠습니다.

- 정렬: `O(N log N)`
- 한 번 순회: `O(N)`
- 전체 시간 복잡도: `O(N log N)`
- 공간 복잡도: `O(N)`

현재 풀이도 정렬을 사용하므로 복잡도 자체는 문제 조건에 적합합니다. 오답의 원인은 시간 초과가 아니라 그룹 인원 갱신 순서입니다.

## 필수 수정

1. `length`를 `1`이 아니라 `0`에서 시작합니다.
2. 현재 모험가를 먼저 그룹에 추가합니다.
3. `length == minimum` 대신 `count >= fear`를 확인합니다.
4. 조건을 만족하는 즉시 그룹을 확정하고 인원 수를 0으로 초기화합니다.
5. `minimum` 변수는 제거합니다. 정렬되어 있으므로 별도로 저장할 필요가 없습니다.

## 선택적 개선

- `sorted([x for x in map(int, input().split())])`보다 `sorted(map(int, input().split()))`가 간결합니다.
- `minimum`이라는 이름은 현재 코드에서 사실상 그룹 내 최대 공포도를 의미하므로, 사용한다면 `max_fear`가 더 정확합니다.
- `input.txt`가 존재하면 코드가 표준 입력보다 `input.txt`를 우선해서 읽습니다. 여러 예시를 모은 `inputs.txt`를 바로 실행하려면 현재 구조에서는 첫 번째 문제 입력만 자동 처리되지 않으므로, 각 블록을 개별 입력으로 테스트해야 합니다.

## 이 문제에서 읽어야 할 신호

다음 조건이 그리디를 떠올리게 합니다.

- 그룹 수의 최댓값을 구한다.
- 공포도 `X`는 그룹 인원이 `X` 이상이어야 한다.
- 공포도를 정렬하면 앞에서부터 조건을 확인할 수 있다.
- 현재 그룹을 빨리 확정할수록 남은 사람을 더 많이 보존할 수 있다.

```text
→ 다음 상태로 초기화
```
